# MANUAL_TEST — feat-015-mo-interop-20261004

Ручные сценарии, которые нельзя покрыть автотестом: (а) агрегация решений двух PreToolUse-хуков на `Bash`
(`prod-guard` + `mo-hook`) на реальном бинарнике `claude` — критерий К20 / REQ-MO-HOOK-9; (б) виден ли модели
stderr `SessionStart`-хука — REQ-MO-SESS-3 «Канал». Исполняется на Verification (`/sdx:manual`) пользователем
или `qa`. **Если выполнить нельзя** — результат записывается как «не проверено» (допущение), не как
«подтверждено»; см. раздел «Если прогон невозможен».

## Шаг 0. Подготовка фикстурного проекта (вне репозитория)
```bash
fx=$(mktemp -d); mkdir -p "$fx/.claude/sdx" "$fx/.mesh" "$fx/dep"; cd "$fx"; git init -q
printf 'PGDENY\n' > .claude/sdx/prod-guard.conf
cat > .mesh/endpoint.yaml <<Y
endpoint_id: e1
node_id: n1
node_path: /x
link: l1
instance: dev
exec_paths: ["$fx/dep"]
on_write: deny
Y
command -v jq python3 && python3 -c 'import yaml' && echo deps-ok
claude --version
```
Запуск: `claude --plugin-dir /home/archi/Code/sdx-claude-plugin` из `$fx` (рабочая копия ветки сессии) — либо
установка из ветки и `/plugin marketplace update sdx`. Убедиться, что загружен `hooks.json` ветки: в `/hooks`
(или `--debug`) видны `mo-hook.sh` и `mo-session.sh`. Инструмент `Bash` предразрешён (allow-правило), чтобы
«молчание» хука не превращалось в запрос разрешения.

что stderr `SessionStart` попадает в контекст.
