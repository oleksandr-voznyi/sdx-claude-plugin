# Change note: feat-016a-simkit-090-20261028

Сессия перевендоринга `sdx/mo/` по политике PROC-028 — `FEAT-016` п.1 (первая из двух сессий 2.4.0). Дельта свёрнута:
бизнес-/технические решения уже зафиксированы в `FEAT-016` и ответной записке SDX 28.10; здесь — исполнение.

## Что сделано
- `sdx/mo/{mesh_endpoint.py,devagent_hook.py,MO-INTEROP.md}` ← sim-kit **0.9.1** из тега `sim-kit-0.9.1` (`9415a29`, 28.10) через
  `git show <tag>:./core/<f>` — не из рабочего дерева. Сначала вендорился 0.9.0 (`3faf4f2`); по решению пользователя на круге 3
  переход на 0.9.1: от 0.9.0 отличаются только `MO-INTEROP.md` (разведены два `## 6`, абзац шаблона §6 под второй признак —
  закрывает находку §4.6 ответной записки) и `KIT = "0.9.1"` в `mesh_endpoint.py`; `devagent_hook.py` байт-в-байт тот же.
  `SIMKIT_VERSION` = `0.9.1`, `SIMKIT_SHA256` пересчитан (`12befd5b…`, `6502cec4…`, `7eec5b88…`), `sha256sum -c` — OK. Промежуточный 0.8.3 пропущен
  (вопрос владельцу — ответная записка §5.1).
- Что изменилось в вендорённом коде между 0.7.3 и 0.9.0 (по diff): хук ставит `sys.dont_write_bytecode` сам (0.7.4);
  `on_write` нормализуется один раз (0.7.4); `from.kit` в конвертах и `KIT = "0.9.0"` (0.7.7); точнее разбор целей
  записи — `DIRECTIONAL` (`cp`/`mv`/`rsync`/`install`/`ln` пишут в последний аргумент), `tar` по флагам, перенаправления
  дескрипторов и `/dev/*` — не цели, нераскрытые `$VAR` — не пути (0.7.7, casino D4); область мандата `.mesh/mandate.yaml`
  → `scope.write` (0.9). Конвенции, на которые опирается обёртка (порядок проверок `endpoint.yaml` → PyYAML; `exit 2` на
  deny; `DENY [MO-exec-paths]` в stderr; `MESH_ENDPOINT_DIR`), не изменились — подтверждено прогоном.
- **Коллизия триады (круг 3, `[триада]`):** `MO-INTEROP.md` §1 с 0.7.7 разрешает dev-agent деплоить самому на инстансы
  `self_deploy` из `endpoint.yaml`, а `agents/devops.md`/REQ-MO-DEVOPS-1 деплой запрещали безусловно — в таком проекте деплой
  не произошёл бы никогда. Решение пользователя: поддержать `self_deploy` — абзац в `devops.md` (режим МО), поправки
  REQ-MO-DEVOPS-1 в SPEC, п.(8) поправки DESIGN, ADR-021 «Последствия».
- `test-mo-hook.sh`: мутант `BYTECODE-FS` снят (хук 0.9.0 не пишет байткод и без переменной — `devagent_hook.py:53`,
  мутант перестал различать); `BYTECODE-ENV` остаётся доказательством гарантии обёртки; `scen9` остаётся проверкой по
  существу. Добавлен сценарий `[8h]` (мандат 0.9 через обёртку: запись вне `scope.paths` → JSON deny с `DENY [MO-scope]`; внутри — тихо;
  `mandate.yaml` без `endpoint.yaml` — тихо), красная сторона — мутант `TRANSLATE` (входит в `SCEN8_MIN`). Добавлен `[8h4]` — независимость `mandate.on_write` от `endpoint.on_write`. 115 проверок / 12 мутантов.
- `sdx/hooks/mo-hook.sh`: код не менялся; поправлен комментарий-контракт в шапке (собственный stderr обёртки — не более
  строки; stderr хука при `exit 0` пробрасывается как есть и под мандатом может быть многострочным).
- Проза: `sdx/protocol.md` («граница (г)» переписана целиком; добавлена граница (д) — промежуточное состояние до `FEAT-016`:
  `mandate.yaml` обёрткой не охраняется, второй источник режима не читается, новый исход `DENY [MO-scope]`/`notice`;
  политика отказа — «та же в текущей вендорённой версии»), `docs/DECISIONS.md` ADR-021 п.5 и датированная поправка к «Последствиям» (байткод, снятый мутант, норма Deployment подтверждена),
  `docs/specs/mo-interop.md` (поправка: REQ-MO-VEND-1, критерий 1, `DH:N`, REQ-MO-DEVOPS-2, REQ-MO-HOOK-7, норма Deployment
  согласована с 0.7.4), `docs/designs/mo-interop.md` (единый датированный блок поправки из восьми пунктов в начале документа + две встроенные
  пометки — к п.1 и к блоку о байткоде), `agents/devops.md` (абзац о флаге),
  `sdx/mo/README.md` (упоминание области мандата). Число *вендорённой* версии в протоколе/ADR не называется (PROC-028 п.2) — только в
  SPEC/DESIGN как исторический факт поставки; исторические маркеры выпусков эталона («с 0.7.4», «0.7.7») — не вендорённая версия.
- Шаг PROC-028 п.3 «релизные заметки с номером версии sim-kit» — выполняется на Closeout (глобальный лог) и при следующем
  релизе плагина (накопительные заметки, выпуск — по явному запросу); в этой дельте не отражён намеренно. README/README.en/CLAUDE.md версии не называют — без правок.

## Границы
**Промежуточное состояние до второй сессии `FEAT-016`:** после мёржа в `main` плагин несёт хук 0.9.0, и в проекте, где узел уже
выдал `.mesh/mandate.yaml`, запись вне `scope.paths` будет давать `notice {scope.write}` узлу или блок по `mandate.on_write: deny`
(через обёртку, сценарий `[8h]`) — без показа мандата на старте и без гейта стадий. Это ожидаемое поведение эталона, не дефект;
SDX-слой его не маскирует. Без мандата поведение SDX-слоя не меняется (обёртки `mo-hook.sh`/`mo-session.sh` не правились). Второй источник режима
`mandate.on_write`, отказ правок `.mesh/mandate.yaml`, показ мандата, гейт `mandate.stages`, `tests/suites.yaml` — вторая
сессия `FEAT-016` (п.2–9). Два заголовка `## 6` в `MO-INTEROP.md` 0.9.0 — находка upstream (ответная записка §4.6), не правится.
