# Change note: feat-016a-simkit-090-20261028

Сессия перевендоринга `sdx/mo/` по политике PROC-028 — `FEAT-016` п.1 (первая из двух сессий 2.4.0). Дельта свёрнута:
бизнес-/технические решения уже зафиксированы в `FEAT-016` и ответной записке SDX 28.10; здесь — исполнение.

## Что сделано
- `sdx/mo/{mesh_endpoint.py,devagent_hook.py,MO-INTEROP.md}` ← sim-kit **0.9.0** из тега `sim-kit-0.9.0` (`3faf4f2`, 26.10) через
  `git show <tag>:./core/<f>` — не из рабочего дерева (HEAD `aibok` на два файла впереди тега). `SIMKIT_VERSION` = `0.9.0`,
  `SIMKIT_SHA256` пересчитан (`8dcd2664…`, `6502cec4…`, `2b051842…`), `sha256sum -c` — OK. Промежуточный 0.8.3 пропущен
  (вопрос владельцу — ответная записка §5.1).
- Что изменилось в вендорённом коде между 0.7.3 и 0.9.0 (по diff): хук ставит `sys.dont_write_bytecode` сам (0.7.4);
  `on_write` нормализуется один раз (0.7.4); `from.kit` в конвертах и `KIT = "0.9.0"` (0.7.7); точнее разбор целей
  записи — `DIRECTIONAL` (`cp`/`mv`/`rsync`/`install`/`ln` пишут в последний аргумент), `tar` по флагам, перенаправления
  дескрипторов и `/dev/*` — не цели, нераскрытые `$VAR` — не пути (0.7.7, casino D4); область мандата `.mesh/mandate.yaml`
  → `scope.write` (0.9). Конвенции, на которые опирается обёртка (порядок проверок `endpoint.yaml` → PyYAML; `exit 2` на
  deny; `DENY [MO-exec-paths]` в stderr; `MESH_ENDPOINT_DIR`), не изменились — подтверждено прогоном.
- `test-mo-hook.sh`: мутант `BYTECODE-FS` снят (хук 0.9.0 не пишет байткод и без переменной — `devagent_hook.py:53`,
  мутант перестал различать); `BYTECODE-ENV` остаётся доказательством гарантии обёртки; `scen9` остаётся проверкой по
  существу. Добавлен сценарий `[8h]` (мандат 0.9 через обёртку: запись вне `scope.paths` → JSON deny с `DENY [MO-scope]`; внутри — тихо;
  `mandate.yaml` без `endpoint.yaml` — тихо), красная сторона — мутант `TRANSLATE` (входит в `SCEN8_MIN`). Добавлен `[8h4]` — независимость `mandate.on_write` от `endpoint.on_write`. 115 проверок / 12 мутантов.
- Проза: `sdx/protocol.md` («граница (г)» переписана; политика отказа «та же в 0.9.0»), `docs/DECISIONS.md` ADR-021 п.5 и датированная поправка к «Последствиям» (байткод, снятый мутант, норма Deployment подтверждена),
  `docs/specs/mo-interop.md` (поправка: REQ-MO-VEND-1, критерий 1, `DH:N`, REQ-MO-DEVOPS-2, REQ-MO-HOOK-7, норма Deployment

  `sdx/mo/README.md` (упоминание области мандата). Число версии в протоколе/ADR не называется (PROC-028 п.2) — только в SPEC/DESIGN

## Границы
**Промежуточное состояние до второй сессии `FEAT-016`:** после мёржа в `main` плагин несёт хук 0.9.0, и в проекте, где узел уже
выдал `.mesh/mandate.yaml`, запись вне `scope.paths` будет давать `notice {scope.write}` узлу или блок по `mandate.on_write: deny`
(через обёртку, сценарий `[8h]`) — без показа мандата на старте и без гейта стадий. Это ожидаемое поведение эталона, не дефект;
SDX-слой его не маскирует. Без мандата поведение SDX-слоя не меняется (обёртки `mo-hook.sh`/`mo-session.sh` не правились). Второй источник режима
`mandate.on_write`, отказ правок `.mesh/mandate.yaml`, показ мандата, гейт `mandate.stages`, `tests/suites.yaml` — вторая
сессия `FEAT-016` (п.2–9). Два заголовка `## 6` в `MO-INTEROP.md` 0.9.0 — находка upstream (ответная записка §4.6), не правится.
