## Находки

### [WARN] [Когерентность] Постоянная дельта спецификации не отражает поправку REQ-PKG-2 (в) круга 3
- Где: `docs/specs/mo-interop.md`, «Дельты FEAT-017», пункт REQ-PKG-1…7 (diff :481)
- Суть: дельта по-прежнему перечисляет условия входа «этап `Closeout` либо вызов из `/sdx:archive`». Из полного SPEC (REQ-PKG-2: «нарушение любого условия — отказ») читатель выведет отказ вне Closeout. Поправка круга 3 и `pr.md` P1 при прямом вызове на любом этапе выполняют прелюдию `archive.md`. Именно это было предметом FAIL-2 круга 3: в сессионной триаде оно закрыто, в постоянный документ не перенесено.
- Ожидалось: в дельте написано «этап `Closeout` (прямой вызов на любом этапе сначала выполняет прелюдию `/sdx:archive`: гейт входа и цикл `next`; отказ — только при нарушении (а)/(б) или если `Closeout` недостижим)».
- Фактически: прежняя формулировка круга 1.

### [WARN] [Когерентность] `protocol.md:321` — прежнее «Мост Closeout (при любом определённом `delivery`)»
- Где: `sdx/protocol.md:321`, «Три слоя границы области» (контекст diff, строка не правилась)
- Суть: по единой классификации «мост» означает только `artifact.offer` (`bridge:offer`). Абзац того же файла называет мостом Closeout при любом определённом `delivery`. Сторож `chk_closeout_taxonomy` ловит дрейф только в строках с «пакет» и формой «любым определённым», поэтому эту строку не видит.
- Ожидалось: «Closeout при мандате — „пакет“ (`pr|branch`, `/sdx:pr`) или „мост“ (`artifact.offer`, `bridge:offer`) — см. «Контракт закрытия сессии»». По желанию: расширить шаблон дрейфа сторожа на «Мост Closeout (при любом определённом».
- Фактически: формулировка FEAT-016.

### [WARN] [Корректность] `start.md` 1б(ii-а): в списке «всех полей» снимка указан `scope`, которого в снимке нет
- Где: `commands/start.md`, шаг 1б (ii-а) (diff :319)
- Суть: показ «целиком — все поля (`commitment`, `title`, `executor`, `scope`, `repo`, …)». Однако `oi_snapshot` (`order-import.sh`) не пишет `scope`: мандат в снимок не копируется (DESIGN «Схема данных», снимок заказа). Область из заказа (`body.mandate.scope` в `dev.py:566`) скрипт не извлекает вовсе. Модель будет искать отсутствующее поле или выдаст область локального мандата за данные заказа. Смысл «целиком» (весь `order.yaml`) от этого не страдает.
- Ожидалось: убрать `scope` из списка полей снимка и оговорить, что область показывает шаг 1а из локального мандата (как в (v)). Либо добавить область заказа в снимок и показ.
- Фактически: перечислено поле, которого нет.

## Безопасность (проверка (3)) — без блокирующих находок
- git: рабочее дерево и индекс не трогаются (plumbing, временный индекс, `commit-tree` без хуков). Ветка пакета пишется CAS-`update-ref` (создание — со «старым» из нулей). Force нет. Публикуется только `change/*` явным refspec, `-c push.default=nothing -c push.followTags=false`, `GIT_ALLOW_PROTOCOL=file:ssh:https:http`, `GIT_TERMINAL_PROMPT=0`, `BatchMode`. Удаление локальной `change/*` на P7 — только по `[деструктив]`. Мутационные прогоны проверяют, что чекаут не тронут.
- Чужие данные: значения заказа, issue, мандата и трейлеров проходят `pr_clean`/`safe`/`jq tojson`. `eval` нет (есть сторож). `gh` и `git` получают аргументы без оболочки. Снимок заказа пишется из показанного пользователю содержимого, повторного чтения нет. Учётные данные URL вырезаются в выводе, JSON и трейлерах (`pr_url_show`, `scrub`, [M] pr-status cred, P7).
