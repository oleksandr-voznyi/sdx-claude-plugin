## Статус реализации

0% (0/19 задач)

## Принцип группировки и порядка задач

Поставка не содержит процедурного кода (см. DESIGN, «Архитектурный обзор» и «Что НЕ меняется в
enforcement-слое») — обычный цикл TDD (тест → код) здесь неприменим ни к одной задаче, кроме двух
финальных ручных прогонов, которые исполняют роль теста. Поэтому:

- **Группировка — по файлу, а не по сквозной теме.** `sdx/protocol.md` правится в 7 местах,
  `CLAUDE.md` — в 2, `README.md`/`README.en.md` — в 4. Одна задача = одна правка одного файла
  целиком (все точки правки этого файла — за один проход одного исполнителя). Причина: если
  разбить правки одного файла на несколько задач разным вызовам `developer`, велик риск
  параллельной/пересекающейся записи в один файл — класс проблемы, уже зафиксированный как
  `PROC-010` (`docs/backlog/PROC-010-parallel-subagents-shared-session-files.md`), и структурное
  решение DESIGN («нет общего изменяемого файла между параллельными вызовами») к самому
  Task Planning не относится — оно про фан-аут `/sdx:audit`, а не про исполнение задач `PLAN.md`.
  Группировка по файлу — тот же принцип на другом уровне: один файл — один писатель.
- **Порядок разорван по одному жёсткому ограничению — ADR-019 не должен иметь входящих ссылок из
  ещё не написанного будущего.** `sdx/protocol.md`, `CLAUDE.md`, `README.md`, `README.en.md`
  ссылаются на ADR-019. Поэтому запись ADR-019 в `docs/DECISIONS.md` — задача T-1, раньше всех
  документов, которые на неё ссылаются.
- **Критерий готовности — не «тест зелёный», а конкретное проверяемое утверждение**: наличие
  строки/раздела в файле, совпадение счётчика с фактом (`ls | wc -l`), разрешение перекрёстной
  ссылки, отсутствие изменений вне заявленного списка файлов. У задач T-18/T-19 критерий — факт
  прогона команды с ожидаемым содержимым отчёта, поскольку автотестов для прозаических
  команд/агентов во фреймворке нет (DESIGN, «Что НЕ меняется в enforcement-слое», последний
  пункт) и это named gap, а не молчаливый пробел.

  иммутабельность), самого инструмента нет (`IDEA-`).

  индекс не заводится.

  «один вектор = один вызов» не гарантирует достаточности на любом масштабе.

- Селективный/авторежимный прогон (`/sdx:audit --vector <CODE>`, `--auto`) — не вводится этой
  поставкой.
