# Change Note — fix-archive-verify-exec-bit-20260725

**Тип:** bug · **Трек:** patch · **Источник:** [BUG-008](../../../docs/backlog/BUG-008-archive-verify-exec-bit-dependency.md)

## Что и зачем

`archive-verify.sh:13` резолвил основную ветку, **исполняя** `lib/default-branch.sh`.
В средах, где установщик плагина срезает режимы (наблюдено:
`~/.claude/remote/plugins/<hash>/`, все `sdx/hooks/**/*.sh` с правами `0600`), подстановка
возвращала пустую строку. `set -uo pipefail` без `-e` выполнение не прерывал, пустой `$def`
уходил в `git branch --merged`, и шаг 7 Closeout выдавал ложный отказ
`[FAIL] ветка sdx/<id> не слита в .` — при фактически слитой ветке. Сообщение уводило
пользователя проверять мёрж, которого проблема не касается.

**Уточнение по находке верификации.** Исходный репорт (и первая редакция этой заметки)
утверждали, что `archive-verify.sh:13` — единственная точка продакшн-кода, зависящая от бита
`x`. Это неверно: боевая проводка `hooks/hooks.json` вызывает пять скриптов
(`preflight`, `stage-gate`, `stage-write-guard`, `prod-guard`, `stop-gate`) **прямым
исполнением**. Проверено: копия `stage-gate.sh` с правами `0600` в форме `hooks.json` даёт
`Permission denied`, `exit 126`. То есть в описанной среде от бита зависят шесть точек, и пять
из них — детерминированный enforcement-слой, отказ которого пользователю не виден вовсе
(DEBT-010). Вывод репорта «остальной слой работает штатно» был следствием невидимости отказа,
а не наблюдением. Поставка чинит все шесть.

## Изменения

1. **`sdx/hooks/archive-verify.sh`** — вызов резолвера приведён к форме
   `bash "$here/lib/default-branch.sh" "$proj"`, уже используемой в `commands/archive.md:70`
   и `commands/verify.md:25`. Скрипт больше не зависит от того, как развёрнут плагин.
2. **`sdx/hooks/archive-verify.sh`** — добавлен явный отказ при пустом `$def`:
   `[FAIL] не удалось определить основную ветку` + `[ABORT]`, exit 1 до любых проверок и до
   деструктива. Пустой ref больше не уходит в git молча (ср. DEBT-010: деградация должна
   называть свою причину, а не маскироваться под содержательный вердикт).
3. **`sdx/hooks/test-archive-verify.sh`** — два сценария:
   - `[10]` копия хука с `lib/*.sh` в режиме `0600` → полный variant-A цикл даёт `[OK]`;
     дополнительно проверяется отсутствие `Permission denied`/`malformed object name` на
     stderr и непустое имя ветки в выводе (та самая «`в .`» из репорта).
   - `[11]` резолвер, успешно возвращающий пустой вывод, → явный `[FAIL]` с названной
     причиной, отсутствие ложного «не слита», ветка не удалена.
4. **Режимы тестов выровнены** (`git update-index --chmod=+x`): `test-prod-guard.sh`,
   `test-stage-gate.sh`, `test-stage-write-guard.sh`, `test-stop-gate.sh` были `100644` при
   `100755` у остальных. На поведение не влияет (их зовут через `bash`), но расхождение
   маскирует находки этого класса при просмотре режимов.
5. **`sdx/protocol.md`** — в описании `archive-verify` зафиксирован новый путь отказа и
   независимость резолва от бита выполнения.
6. **`hooks/hooks.json`** — все пять регистраций переведены на `bash "${CLAUDE_PLUGIN_ROOT}"/…`
   вместо прямого исполнения. Вступает в силу после `/plugin marketplace update sdx`.
7. **`sdx/hooks/test-hook-wiring.sh`** (новый сьют, подхватывается глобом `verify-cmd.sh`) —
   инвариант формы вызова как enforcement: каждая регистрация идёт через `bash`, каждый
   referenced-скрипт существует, плюс сценарий `[4]`, демонстрирующий, что инвариант несущий
   (`0600` + прямой вызов → `exit 126`, через `bash` → `0`).
8. **`sdx/protocol.md`** — инвариант формы вызова назван явно в разделе «Enforcement-слой»
   (снятие WARN 3: граница больше не держится на неявной прозе).
9. **`docs/designs/session-worktree-model.md`** — псевдокод `archive-verify` синхронизирован с
   кодом; заодно два устаревших пути `.claude/sdx/hooks/` → `${CLAUDE_PLUGIN_ROOT}`
   (снятие WARN 1: эталонный псевдокод больше не воспроизводит дефект).
10. **`docs/backlog/BUG-008-*.md` + индекс** — заголовок и раздел «Масштаб зависимости»
    приведены к фактам, добавлен п. 4 рекомендации про `hooks.json`.

## Проверка

- Новые сценарии подтверждены **красными на до-фиксовой версии** хука: воспроизведён точный
  симптом репорта (`Permission denied` → `malformed object name` → `[FAIL] ... не слита в .`),
  5 проваленных ассертов.
- `test-hook-wiring.sh` тоже подтверждён красным на старой проводке: сценарий `[2]` перечисляет
  все пять регистраций как зависящие от бита `x`.
- `bash sdx/hooks/test-archive-verify.sh` → 24/24 PASS.
- `bash .claude/sdx/verify-cmd.sh` → 10/10 сьютов PASS.

## Границы

- Срезание режимов при синхронизации плагина не исправлено и исправлено быть здесь не может —
  это свойство установщика. Поставка снимает зависимость от бита во всех шести точках, поэтому
  обходной путь `chmod +x` больше не нужен.
- Правка `hooks/hooks.json` вступает в силу только после `/plugin marketplace update sdx`:
  рантайм исполняет установленную копию плагина, а не эту рабочую копию.
- Инвариант формы вызова enforced тестом **только для `hooks/hooks.json`**. Вызовы из
  прозаических команд `/sdx:*` (включая `commands/archive.md:78` → сам `archive-verify.sh`)
  остаются конвенцией текста: покрытие здесь видимое, не доказанное.
