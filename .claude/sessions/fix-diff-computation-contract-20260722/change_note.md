# Change Note — fix-diff-computation-contract-20260722

**Трек:** standard · **Тип:** bug · **Источник:** `BUG-004` (audit-2026-07-01 B3), `links: [ADR-004, ADR-005]`.

## Discovery (лёгкий, инлайн)

### Подтверждённое противоречие (BUG-004)
Кто вычисляет diff поставки для fresh-eyes ревью — расходится между командой и агентом:
- `commands/verify.md` шаг 4: **оркестратор** вычисляет diff (`git diff "$def"...sdx/<id> -- . ':!.claude/sessions/**'`), шаг 5 передаёт его ревьюеру «как данные». Ветка резолвится динамически через `default-branch.sh` (ADR-010).
- `agents/reviewer.md` — обратное: «Вход» (стр. 21) и «Инструкция 2» (стр. 62) велят ревьюеру **самому** получить diff через `git diff main...sdx/<id>` (Bash). Frontmatter `tools:` (стр. 5) включает `Bash`.

Два дефекта второго пути (ровно как в BUG-004): (1) двойная токенизация — diff попадает в контексты дважды; (2) дыра в изоляции — `Bash` даёт ревьюеру доступ ко всему (вкл. `session.log`), «стена контекста» держится только на прозе, а не на enforcement.

### Смежный дефект когерентности (найден в Discovery, чинится теми же строками)
`reviewer.md` хардкодит `main` (`git diff main...`), тогда как весь фреймворк резолвит основную ветку динамически (`default-branch.sh`, REQ-BRANCH-3, ADR-010). Даже без BUG-004 это скрытая поломка на репозиториях с иной основной веткой. Исчезает вместе с изъятием самостоятельного вычисления.

### Проверка безопасности изъятия Bash
`grep` по `reviewer.md`: единственное использование `Bash` — вычисление diff (стр. 21, 62). Ни одна другая команда/агент не полагается на Bash ревьюера (`commands/*.md`: `verify.md`/`import.md`/`retrack.md` лишь упоминают, что diff берёт `verify.md` шаг 4). Для оси когерентности (axis 3) ревьюеру достаточно `Read`/`Glob`/`Grep`, чтобы читать файлы репо для сверки. **Вывод: изъятие `Bash` безопасно при условии, что diff подан файлом.**

## Технические решения (Change)

1. **Материализация diff в файл (verify.md).** Шаг 4 перенаправляет diff редиректом в `.claude/sessions/<id>/delivery.diff` — вывод НЕ проходит через контекст оркестратора. Шаг 5 передаёт ревьюеру **путь** к файлу, а не текст diff. Снимает двойную токенизацию (исключение из ADR-005).

2. **reviewer.md — diff как файл, без Bash.**
   - Frontmatter `tools:` → `Read, Write, Glob, Grep` (изъят `Bash`). Контракт изоляции становится **enforcement** (нет инструмента → физически нет доступа к `session.log`/произвольному git), а не договорённостью в прозе.
   - «Вход» и «Инструкция 2»: diff подан файлом `delivery.diff` (путь в постановке) — читать через `Read`, не вычислять. Хардкод `main` удалён (резолв ветки — забота оркестратора в `verify.md`).

3. **Эфемерность delivery.diff (.gitignore + init.md).** Материализованный diff — производный, регенерируемый, эфемерный файл того же класса, что `.stopgate.*` («буфер верификации», REQ-SESS-2). Добавляется targeted-паттерн `.claude/sessions/*/delivery.diff` рядом с существующим `.stopgate.*` в корневом `.gitignore` И в seed-блок `commands/init.md` шаг 2 (чтобы новые проекты получали его). Так файл не пачкает дерево (гейт «чистое дерево» на Closeout/switch) и не коммитится как ложный артефакт.

4. **protocol.md — когерентность триады.** Раздел «Fresh-eyes: контракт изоляции»: отметить, что diff **материализуется в файл** и передаётся путём, а `Bash` у `reviewer` изъят как enforcement стены контекста. Держит триаду «протокол ↔ команда `verify.md` ↔ агент `reviewer.md`» согласованной — это сама ось, ради которой заведён BUG-004.
