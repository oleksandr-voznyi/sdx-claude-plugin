# change_note — fix-stop-gate-exec-bit-20260901

**Запись бэклога:** [DEBT-026](../../../docs/backlog/DEBT-026-stop-gate-verify-cmd-exec-bit.md)
— «`stop-gate` определяет тест-команду по биту выполнения — потеря бита молча снимает тест-пол».

## Discovery: что установлено

**Дефект в коде подтверждён.** `sdx/hooks/stop-gate.sh:41` выбирает per-project раннер
проверкой `[ -x "$proj/.claude/sdx/verify-cmd.sh" ]`. При снятом бите ветка не срабатывает,
управление уходит в автодетект (`composer test`/`npm test`/`phpunit`), а в проекте без этих
маркеров — в `exit 0`. Тест-пол исчезает без единого сообщения.

Риск наблюдался в поле: `BUG-008` зафиксировал среду, где все `sdx/hooks/**/*.sh` развёрнуты
установщиком с правами `0600`.

## Discovery: коллизия триады (стоп по `CLAUDE.md` §4)

**Рекомендация записи опирается на неполную проверку.** `DEBT-026` п.1 просит «проверить, что
нигде не задокументировано снятие бита как способ выключить раннер», и сообщает, что беглый
просмотр `commands/init.md` и `sdx/protocol.md` такой конвенции не обнаружил. Проверка по всему
репозиторию обнаруживает её в двух местах, в эти два файла не входящих:

1. **`ADR-4`** (`docs/designs/phase1-enforcement-routing.md:426`) — «шаблон неисполняемый»,
   с прямым обоснованием механизма: «Проверка `[ -x ... ]` в stop-gate гарантирует, что
   неисполняемый `.template` не подхватится».
2. **Шапка самого шаблона** `sdx/templates/verify-cmd.sh.template` — раздел `HOW TO ACTIVATE`:
   «`cp ... ; chmod +x ...` / Until chmod +x is applied, stop-gate treats this file as
   non-executable and falls back to autodetect».

То есть бит выполнения — **задокументированный ритуал активации**, а не случайное свойство
реализации. Замена `-x` → `-f` его отменяет; это разворот решения `ADR-4`, а не техническая
правка формы вызова.

**Существенное уточнение в пользу правки.** Обоснование `ADR-4` («гарантирует, что `.template`
не подхватится») своим механизмом не обеспечивается: проверка идёт по пути `verify-cmd.sh`, а
шаблон называется `verify-cmd.sh.template` — под `[ -f ]` он не попадёт ровно так же, как не
попадает под `[ -x ]`. От подхвата шаблона защищает **имя файла, а не режим**. Бит здесь несёт
не ту нагрузку, которую ему приписывает ADR.

**Существенное уточнение против правки.** У ритуала есть второй, в `ADR-4` не названный эффект:
пользователь, скопировавший шаблон и ещё не настроивший его под свой стек, защищён от красного
пола заведомо неверной командой (шаблон из коробки вызывает `./vendor/bin/phpunit` — в
Node-проекте это гарантированный отказ). При `-f` такой промежуточный копипаст немедленно
включает пол на команде-заглушке.

## Решение

*Ожидает решения пользователя — коллизия триады останавливает работу в любом `gate_mode`.*
