### [WARN] [Корректность] Раннер теперь всегда интерпретируется bash — шебанг per-project файла игнорируется, и это нигде не сказано

- Где: `sdx/hooks/stop-gate.sh:101` (`bash "$runner"`); контракт — `change_note.md:54-57` и п.5
  «принятый осознанно риск», поправка к `ADR-4` (`docs/designs/phase1-enforcement-routing.md:481-485`),
  `sdx/templates/verify-cmd.sh.template:8-9`, `sdx/protocol.md:233-235`.
- Суть. До поставки раннер исполнялся как `bash -c "$cmd"`, где `cmd` — путь: строку разбирал шелл,
  дальше `execve` пути, и **ядро читало шебанг**. Раннер на любом интерпретаторе (`#!/usr/bin/env python3`,
  `zsh`, `sh` с иной семантикой) работал, если стоял бит `x`. Теперь файл безусловно скармливается
  `bash`. Для проекта, у которого `.claude/sdx/verify-cmd.sh` написан не на bash, обновление плагина
  превращает зелёный тест-пол в **постоянно красный** (bash подавится чужим синтаксисом) — то есть
  ровно «блокировка завершения хода на заведомо неверной команде», от которой поставка предупреждает,
  но только для другого случая (ненастроенная копия шаблона).
- Ожидалось / фактически. Ожидалось: раз поставка меняет форму вызова, полный перечень изменившегося
  поведения назван там же, где назван первый принятый риск. Фактически: `change_note.md:63-65` называет
  ровно один риск; шапка шаблона (`:9`) констатирует форму («stop-gate runs the file as `bash <path>`»),
  но не следствие для шебанга; детект `/sdx:reconcile` (`commands/reconcile.md:52`) ключуется на
  `[ -f ] && [ ! -x ]` и этот подслучай (файл исполняем, но не bash) не ловит **вообще**.
- Почему WARN, а не FAIL: ни один артефакт триады не обещает свободу интерпретатора — файл называется
  `verify-cmd.sh`, шаблон бэшевый, инвариант формы вызова BUG-008 (`sdx/protocol.md:205-213`) предписывает
  `bash <путь>` для слоя. Противоречия контракту нет; есть неназванное следствие, требующее квитирования
  (закрывается одной строкой в шапке шаблона и/или в поправке к ADR-4).
- Чем проверено: чтение `sdx/hooks/stop-gate.sh:99-105` против пред-поставочной формы в `delivery.diff:175`;
  `commands/reconcile.md:52-61`; `sdx/templates/verify-cmd.sh.template:1-22`; `sdx/protocol.md:198,205-213`.
