## Сознательно не взято в скоуп
- **`--work-dir` как отдельный режим хранения состояния** (записка §2.1) — не заведено: ответ Q2 показывает, что
  `history`/`docs_in_repo` закрываются местом клона и существующим Closeout (`git rm -r` каталога сессии); отдельный
  контракт Closeout стоил бы пересмотра ADR-012/REQ-SESS-1 без нужды для П3/П4. Вернуться, если пилот покажет обратное.
- **Промежуточный перевендоринг 0.8.3** (записка §2.7) — не заведено: `FEAT-016` берёт сразу 0.9.0 (тег есть, правки
  0.7.4 учтены); подтверждение запрошено у владельца (ответ §5.1).
- **Замена `prod-guard`/`stop-gate` аудитом узла** (записка §2.5) — отклонено по существу (ответ §2.1): разные гейты
  (актора / системы); записи не требует.
- **Поддержка GitLab/Gitea в `/sdx:pr`** — не заведено: по первому заказчику; `FEAT-017` ограничен `gh` + `bare`.
- **Находки по sim-kit** (ответ §4.1–4.7) — репозиторий `aibok`, бэклог плагина не ведёт; статус — по ответной записке.
- **Записка §2.4: уведомление при переключении ветки вне `branches` и пути `paths`, приходящие с арендой `lease.granted`** —
  в хуке sim-kit 0.9.0 этого нет (область берётся из мандата, не из аренды; переключения веток хук не видит); на стороне SDX
  делать нечего до изменения эталона — адресовано владельцу sim-kit, записи нет.
- **Записка §2.1: `sdx run spec|design|plan`** — не заведено: П3 ограничен `execute`/`verify`/`audit` (§5 п.5), см. `FEAT-018` п.4.
- **Записка §2.9: «окружение» набора тестов** — поле в `tests/suites.yaml` эталоном не читается (`dev.py:285–312`: `cmd`,
  `budget_min`, `selector`); до появления в sim-kit SDX его не генерирует.
- **Отдельный ADR «SDX как библиотека стадий под внешним мандатом»** — не заведён: ADR появится в `FEAT-016`
