- Суть: PROC-028 р.5 требует сторож для поверхностей, которые пересказывают состав `sdx/mo/` (README плагина, `CLAUDE.md`). В Решении 6 строка в README отложена до FEAT-015 с обоснованием «сторож `PROC-027` на README тогда и сработает». Такого сторожа в репозитории нет. `PROC-027` открыт. Сьют этой поставки закрывает другую сверку (каталог против `SIMKIT_SHA256`), а не р.5. Кроме того, поставка сама заводит две новые непроверяемые поверхности с перечнем вендорённых файлов: `DECISIONS.md:227` и `protocol.md:282` (`mesh_endpoint.py`, `devagent_hook.py`, `MO-INTEROP.md`). В «Границах» отказ от р.5 не назван.
- Ожидалось: р.5 либо покрыт, либо назван в «Границах» с верным адресом переноса (на `PROC-027`/`FEAT-015`). Только тогда `PROC-028` можно закрывать на Closeout.
- Фактически: контракт утверждает факт о кодовой базе, которого нет, и опирается на него. Это коллизия «артефакт ↔ codebase».

### [WARN] [Когерентность / Корректность] Исключение `__pycache__` и правило «плоский каталог» нигде не задокументированы и противоречат инварианту ADR-013, заявленному «без оговорок»
- Где: `sdx/hooks/test-mo-inventory.sh:83` (`case ... README.md|__pycache__) continue`), `:79` (комментарий «flat directory by contract»), `:84` (`unexpected subdirectory`); заголовок `:17`; `docs/DECISIONS.md:234-235`
- Суть:
  1. В перечне исключений четыре имени, а в заголовке (d), в `change_note.md:29` (п.3) и в `protocol.md:298-299` их три. Исключение `__pycache__` не описано ни в одном артефакте.
  2. Правило «подкаталог — сам по себе находка» и «flat directory by contract» в контракте тоже отсутствует.
  3. По смыслу исключение ждёт, что в `sdx/mo/` появится `__pycache__`. Это возможно, только если python пишет байткод рядом с вендорённым кодом при запуске хука (`FEAT-015` п.2: `python3 …/sdx/mo/devagent_hook.py`). В мета-репозитории такой каталог к тому же стал бы untracked: в `.gitignore` нет `__pycache__`, а инвариант 1 `archive-verify` проверяет чистоту дерева.
- Ожидалось: исключение и правило плоского каталога объявлены в контракте и протоколе, а противоречие с инвариантом разрешено явно. Например, нормой для FEAT-015 «запуск без записи байткода» без исключения в стороже, либо названной оговоркой в ADR.

### [INFO] [Корректность] Грамматика строк `SIMKIT_SHA256` уже, чем «вывод `sha256sum`»
- Где: `test-mo-inventory.sh:68` — `^[0-9a-f]{64}  [^/ ][^ ]*$`
- Суть:
  1. Имена с пробелами отклоняются как malformed. Пробелы в пути к корню репозитория обрабатываются корректно: везде кавычки, `${f#"$d"/}`.
  2. Проходят `../x` и `sub/x`. Первое — ссылка за пределы каталога, второе противоречит правилу плоского каталога из (d).
  3. Строка бинарного режима `<hash> *name` проходит регулярку и даёт вводящее в заблуждение «listed but missing: *name».
  4. GNU `sha256sum` для имён с `\` предваряет вывод символом `\`, и тогда `cut -f1` даст ложный mismatch.

  Для трёх текущих имён всё это неактуально.
