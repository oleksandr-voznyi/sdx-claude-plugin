## Находки

### [FAIL] [Когерентность/Корректность] Гард чистого дерева делает `/sdx:resume` неприменимой к `no_gates`-сессиям, которым `DESIGN.md` её обещает

- Где: `commands/resume.md:23-30` (гард) и `commands/resume.md:62` (ветка продолжения при
  `no_gates == true`); `delivery.diff:140-147` и `:179`; контракт — `DESIGN.md:411-414`
  («Обработка ошибок и Граничные случаи»), `sdx/protocol.md:643-647`.
- Суть: гард сформулирован безусловно — «если `git status --porcelain` непусто, СТОП, закоммить
  или отменить незакоммиченные изменения». Но у сессии с `no_gates == true` на `Execution`
  незакоммиченный код прототипа — это **нормальное, санкционированное состояние**: `CLAUDE.md` §4
  называет его единственным именованным исключением из `REQ-SESS-1`, а `commands/switch.md:15` —
  тот самый гард, на симметрию с которым ссылается `resume.md`, — содержит явную оговорку:
  «Если у текущей сессии `no_gates == true` на этапе `Execution`, коммит НЕ является требованием
  (REQ-VIBE-3/9)… штатный путь — `git stash`». В `resume.md` этой оговорки нет ни в каком виде.
  Следствия, каждое проверяемо:
  1. `DESIGN.md:411-414` утверждает «`/sdx:resume` работает и для неё [сессии-прототипа] …
     продолжение — возврат к исходной текстовой цели прототипирования». Фактически для
     прототипа в типичном состоянии команда останавливается на шаге 2 и до шага 5 не доходит —
     третий буллет шага 5 (`no_gates == true`) недостижим при обычном ходе прототипирования.
  2. Инструкция, которую в этом случае получает пользователь, требует ровно тех двух действий,
     которые фреймворк для прототипа запрещает или которые уничтожают работу: «закоммить» (нарушает
     исключение ADR-018/ADR-020: первый коммит кода прототипа снимает исключение только при
     легализации через `/sdx:proto`) либо «отмени незакоммиченные изменения» (уничтожает прототип).
     Вариант `git stash`, штатный для этого случая по `switch.md`, не назван.
  3. Утверждение `resume.md:24` «симметрично гарду `commands/switch.md`» фактически неверно:
     гард `switch.md` не безусловен, у него есть именно та оговорка, которой здесь нет. Это
     пользовательский текст, утверждающий свойство, которого механизм не имеет.
- Ожидалось: либо гард с явной `no_gates`-оговоркой (стэш/пропуск проверки для некоммиченного кода
  прототипа при сохранении отказа для служебных файлов сессии), либо `DESIGN.md` и `resume.md`
  честно объявляют `/sdx:resume` неприменимой при `no_gates == true` и убирают недостижимую ветку
  шага 5 и обещание в «Граничных случаях».
- Фактически: безусловный гард + недостижимая ветка продолжения + ложная ссылка на симметрию с
  `switch.md`. Ни один сценарий `test-resume-contract.sh` этот случай не трогает (`[T15]` строит
  грязное дерево только в обычной сессии), `MANUAL_TEST.md` — тоже (шаг 4 моделирует `no_gates`,
  но только для `/sdx:proto`, не для `/sdx:resume`).

  `:231-248` (шаг 7), `:273-275` (предусловие шага 7а), `:300-306` (критерий шага 7а).
- Суть: раздел «Метод» заявляет, что шаги 1-7а исполнены разными агентами, **каждый на своей

  (шаг опирается на журнал, накопленный ими, и считает записи до/после — поэтому его нельзя
  прогонять в отрыве от предшествующих). Запись `[FAIL]` от Шага 2 и запись `[триаж]` от Шага 7
  уже в журнале». Критерий шага 7а (`tagged "$d" FAIL -eq 2`) измерим только на накопленном
  журнале. При этом результаты сообщают «Шаг 2 … исполнен в составе шага 7а» и «Шаг 7 … исполнен в
  составе шага 6» — то есть ни шаг 2, ни шаг 7 не исполнялись как написаны, а шаг 6 закрыл
  категорию `[триаж]` другим сценарием (триаж проваленного ручного шага), чем шаг 7
  (WARN-квитирование по `verification_report.md`, с собственным критерием «`auto_decisions.md` не
  создан», о котором результат шага 6 не сообщает ничего). Итог «passed 10 / failed 0» тем самым
  считает исполненными шаги, для которых предъявлено исполнение другого сценария.
- Ожидалось / Фактически: либо прогон одной накопительной фикстурой, как предписывает шаг 7а, либо
  переписанные предусловия/критерии под фактический метод (одноразовые фикстуры) — фактически
  оставлены оба взаимоисключающих утверждения, а фикстуры `mktemp` уничтожены, так что числа
  (`[FAIL] == 2`, прирост `== 1`) не воспроизводимы и не перепроверяемы по поставке.

### [WARN-7] [Корректность] `commands/proto.md`: разорвана цепочка `&&` — `git commit` теперь выполняется независимо от исхода `git add`

  Синтаксис самих вставок корректен (`; \` + перевод строки — валидное продолжение строки).
- Ожидалось / Фактически: сохранить `&&` там, где он был («`git add A B && { if …; fi; } && git commit`»

### [WARN-8] [Корректность] Overclaim-lint направленный и после `normalize` работает по всему файлу как по одной строке

- Где: `sdx/hooks/test-resume-contract.sh` `[T24](2)` (`delivery.diff:996, 1027-1042`),
  `normalize()` (`delivery.diff:361`).
- Суть, обе стороны:
  - **Пропускает годный брак.** `OVERCLAIM_RE='восстанавливает.*(полностью|без каких-либо потерь)'`
    не ловит естественный порядок слов «**полностью восстанавливает** прогон» — прямой overclaim,
    который критерий приёмки `SPEC.md:187-188` запрещает. Красная ветка сконструирована ровно под
    порядок, который регулярка ловит («восстанавливает состояние полностью»), поэтому зелёная
    сторона выглядит доказанной шире, чем она есть.
