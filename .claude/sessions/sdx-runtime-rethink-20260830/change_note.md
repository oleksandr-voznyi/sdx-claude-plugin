# Change note — сессия `sdx-runtime-rethink-20260830`

- **Тип / трек**: `intake` / `doc` (жёсткая привязка, ADR-017)
- **Этап**: `Update`
- **Содержательный документ разбора**: `intake.md` в каталоге сессии → на Closeout переносится в
  `docs/history/intake/sdx-runtime-rethink-20260830.md`

## Резюме

Разобран внешний стратегический материал по переосмыслению SDX: фреймворк рассмотрен как
design-time двойник ядра durable-оркестратора, проведён аудит его durable-свойств, предложена
модель полномочий по классу риска действия в связке с картой освоенности областей проекта
(`declared` + `observed`), и обоснован снос машинерии треков/этапов. Материал превращён в
26 новых записей `docs/backlog/` с собственной шкалой волн 1–5; реализация ничего из этого в
скоуп сессии не входила — `intake` порождает записи, а не выполняет их.

выполнения. Все 62 уникальные цели поля `links` разрешаются (12 ADR + 24 существующие записи + 26 записей
этого прогона), битых ссылок нет.

практику нормой и уточнить определение `intake` в протоколе — или ограничить `intake` create-путём.

### Квитирование оставшегося WARN

**поставка не откатывается.** Обязательство, переносимое на Closeout: завести `PROC-`запись —
уточнить определение типа `intake` в `sdx/protocol.md`, а именно вправе ли он (а) дополнять
существующие записи бэклога связями и (б) вести слой сверки против закрытых записей, или обе
операции остаются исключительно за типом `audit`. Эта же запись закрывает требование п.4
Closeout-чек-листа о минимум одной НОВОЙ записи бэклога для типа `intake`.
