## Находки

### [FAIL] [Корректность] Блок «Провенанс» в `FEAT-005` утверждает о репозитории неправду и противоречит телу той же записи

- Где: `docs/backlog/FEAT-005-stop-hook-scheduler-tick.md:32-35` (добавлен ремедиацией WARN-9);
  противоречащее место — `FEAT-005:15-17`
- Суть: блок объявляет единственный названный им факт — «способность хука `Stop` отказать в
  завершении хода и вернуть модели причину» — взятым из внешнего материала, «в репозиторий не
  входящего, и из репозитория непроверяем**ым**». Этот факт проверяется по репозиторию тремя
  независимыми местами:
  - `hooks/hooks.json:37` — событие `Stop` зарегистрировано в проводке хуков плагина;
  - `sdx/hooks/stop-gate.sh:3` — «Stop hook. exit 2 + stderr blocks turn-end until the verify
    command is green» (и отказ, и возврат причины моделью через stderr);
  - `sdx/protocol.md:196` — «**stop-gate** (Stop): тест-прогон как пол под Verification; ход не
    завершается на красном».

  Более того, тело самой записи двумя абзацами выше (`FEAT-005:15-17`) утверждает обратное блоку:
  «в харнессе уже есть точка… Сейчас она используется только для прогона тестов (`stop-gate`)», а
  `FEAT-005:24-25` опирается на loop-guard и green-run cache (`ADR-011`) как на работающие
  механики того же хука.
- Ожидалось / Фактически: ожидалось — провенанс на тех фактах, которые из репозитория
  действительно непроверяемы (для `FEAT-005` таких названо ноль). Фактически — в постоянную запись
  бэклога внесено ложное утверждение о состоянии репозитория, прямо противоречащее соседнему
  абзацу той же записи. Правка WARN-9 в этой записи не устранила находку, а породила новую:
  запись стала внутренне противоречивой. Цена исправления — одно предложение (либо снять блок в
  `FEAT-005`, либо переформулировать его на действительно внешний факт).
