description: Гейт принятия/отклонения прототипа (режим no_gates): показать результат, принять с легализацией или откатить точечно.
---

Ты выполняешь роль Session Manager. Твоя задача — провести пользователя через гейт принятия/отклонения экстремального прототипа (флаг `no_gates == true`, тип сессии `proto`, этап `Execution`): честно предъявить фактический результат текущей попытки и, по явному решению пользователя, либо направить прототип в легализацию, либо откатить его точечно до состояния baseline. Эта команда — единственный путь легализации прототипа (никакой другой команды для этого не существует, REQ-LEGAL-1); вызывай её самостоятельно, не полагаясь на контекст, накопленный ранее в этой же сессии.

Алгоритм:

1. **Проверка `no_gates`/`stage`.** Определи текущую сессию по активной git-ветке (`git branch --show-current`, ветки вида `sdx/<id>`) и прочитай `.claude/sessions/<id>/session_state.json`.
   - Если `no_gates != true` → ОСТАНОВИСЬ: сообщи, что команда `/sdx:proto` применима только к сессиям с активным флагом `no_gates` (заведённым как `/sdx:start proto "<цель>"`, REQ-LEGAL-3).
   - Если `stage != "Execution"` → ОСТАНОВИСЬ и укажи пользователю текущий этап: при `no_gates == true` сессия структурно обязана оставаться на `Execution` (REQ-LEGAL-1) — расхождение сигнализирует о повреждённом/вручную изменённом состоянии, разбирайся вручную (`git log -p -- .claude/sessions/<id>/session_state.json`), а не продолжай гейт вслепую.

2. **Чтение `prototype_baseline.txt` — fail-closed.** Прочитай `.claude/sessions/<id>/prototype_baseline.txt`. Формат (машиночитаемый, `.txt`, не `.md`):
   ```
   # SDX vibe prototype baseline
   attempt 1
   started 2026-07-20 14:05:11
   rev 9f3c1a2b4d5e6f708192a3b4c5d6e7f8091a2b3c
   untracked notes/scratch.txt
   untracked tmp/local.env
   ```
   - `attempt N` — номер текущей попытки прототипа (растёт при каждом отклонении).
   - `rev` — коммит, относительно которого считается tracked-дельта прототипа.
   - `untracked <path>` (0..N строк) — untracked-файлы, существовавшие ДО начала этой попытки; project-relative пути, ровно как их печатает `git ls-files --others`. Эти строки исключаются из списка отката, чтобы не задеть посторонние файлы пользователя.

   Запомни `N` (значение `attempt` — номер ЗАВЕРШАЮЩЕЙСЯ попытки) — понадобится на шаге 6; там же используется `N+1` — номер НОВОЙ попытки, стартующей после отката.

   **Если файл отсутствует, пуст, не содержит строку `rev`, либо `rev` не резолвится в существующий коммит** (`git rev-parse --verify --quiet "<rev>^{commit}"` не возвращает ничего) — **ОСТАНОВИСЬ. Baseline НИКОГДА не додумывается из `HEAD` и откат в этом случае НЕ предлагается.** Точечность отката без валидного baseline недоказуема — это ровно тот класс ошибки, который уничтожил бы чужие файлы. Сообщи пользователю дословно, что произошло, и предложи разобрать состояние дерева вручную (`git status`, `git diff`).

3. **Вычисление списка файлов прототипа.** Выполни дословно:
   ```bash
   sdir=".claude/sessions/<id>"
   base_rev="$(awk '$1=="rev"{print $2; exit}' "$sdir/prototype_baseline.txt")"
   git rev-parse --verify --quiet "${base_rev}^{commit}" >/dev/null || {
     echo "SDX proto: baseline-ревизия ${base_rev} не найдена — точечный откат недоказуем." >&2; exit 1; }

   tmp_tracked="$(mktemp)"; tmp_new="$(mktemp)"

   # (1) tracked-дельта: изменённые, удалённые и добавленные-в-индекс файлы против baseline.
   #     `git diff --name-only <rev>` сравнивает РАБОЧЕЕ ДЕРЕВО с ревизией, поэтому покрывает
   #     и staged, и unstaged. Каталог артефактов сессии исключён — он живёт своей жизнью.
   #     `-c core.quotePath=false` — иначе не-ASCII пути печатаются в C-кавычках
   #     (`"\320\272..."`) и не совпадают с реальными именами файлов ниже по пайплайну.
   git -c core.quotePath=false diff --name-only "$base_rev" -- . ':!.claude/sessions/**' > "$tmp_tracked"

   # (2) новые untracked = untracked сейчас МИНУС untracked, записанные в baseline.
   comm -23 \
     <(git ls-files --others --exclude-standard -z | tr '\0' '\n' | sed '/^$/d' \
         | grep -v '^\.claude/sessions/' | LC_ALL=C sort) \
     <(sed -n 's/^untracked //p' "$sdir/prototype_baseline.txt" | LC_ALL=C sort) \
     > "$tmp_new"
   ```
   Если оба файла (`$tmp_tracked` и `$tmp_new`) пусты — сообщи пользователю «прототип не произвёл изменений» и заверши команду БЕЗ гейта (нечего принимать, нечего откатывать); удали временные файлы (`rm -f "$tmp_tracked" "$tmp_new"`) и остановись здесь.

4. **Предъявление результата.** Покажи пользователю:
   - сводку: `attempt N`, число изменённых tracked-файлов (строк в `$tmp_tracked`), число новых файлов (строк в `$tmp_new`), `git diff --stat "$base_rev" -- . ':!.claude/sessions/**'`;
   - полный список новых файлов из `$tmp_new` (путь + число строк каждого файла);
   - дифф tracked-файлов: `git diff "$base_rev" -- . ':!.claude/sessions/**'`. Если он длиннее примерно 400 строк — вместо полного текста покажи `--stat` и первые 200 строк, предложи развернуть дифф полностью по отдельному запросу.

5. **`AskUserQuestion` — безусловно, независимо от `gate_mode` (REQ-VIBE-10).** Этот гейт интерактивен ВСЕГДА, в том числе при `gate_mode: "auto"` — не пропускай его и не подставляй дефолт вместо ответа пользователя.
   - Если `gate_mode == "auto"` — перед вопросом выведи одну строку: «стоп-рубрика протокола: деструктивная операция + продуктовое суждение — авторежим здесь не действует». В `auto_decisions.md` НИЧЕГО не записывай: дефолта, который можно было бы принять автоматически, для этого решения не существует.
   - Три варианта ответа:
     - **Принять** — прототип достиг цели, переходим к легализации.
     - **Отклонить** — откатить показанный список файлов до состояния baseline.
     - **Продолжить работу** — выйти без действий: пользователь не обязан принимать решение прямо сейчас (неразрушающий третий выход).

6. **Ветка «Отклонить» — точечный откат.** Выполни ТОЛЬКО после явного ответа «Отклонить». Список и дифф уже были предъявлены на шаге 4 как часть самого решения (REQ-VIBE-5) — повторного подтверждения НЕ запрашивай, второе «вы уверены?» обесценило бы первое.

   **Пересчёт списка обязателен — не полагайся на переменные шага 3.** Между шагом 3 и этой точкой пройдена `AskUserQuestion` (шаг 5): shell-сессия, в которой на шаге 3 были вычислены `$base_rev`/`$tmp_tracked`/`$tmp_new`, к этому моменту гарантированно завершена — ни переменные, ни временные файлы `mktemp` больше не существуют. Рабочее дерево между шагом 3 и этой точкой не менялось (единственное действие пользователя — ответ на вопрос), поэтому пересчёт по тому же `prototype_baseline.txt` даёт ровно тот список, что был показан на шаге 4. Весь блок ниже — **один непрерывный bash-блок**, исполняемый одним ходом: сначала пересчёт (дословно тот же фрагмент, что и на шаге 3 этой команды), сразу за ним — fail-closed гард на закавыченные git'ом пути (`"`/`\` в имени — точечный откат по такому пути недоказуем, останавливаемся), затем сам откат. **Никогда не используй `git clean -fd`, `git checkout .` или `git reset --hard`** — только поимённые операции по спискам `$tmp_tracked`/`$tmp_new`:
   ```bash
   sdir=".claude/sessions/<id>"
   base_rev="$(awk '$1=="rev"{print $2; exit}' "$sdir/prototype_baseline.txt")"
   git rev-parse --verify --quiet "${base_rev}^{commit}" >/dev/null || {
     echo "SDX proto: baseline-ревизия ${base_rev} не найдена — точечный откат недоказуем." >&2; exit 1; }

   tmp_tracked="$(mktemp)"; tmp_new="$(mktemp)"

   # (1) tracked-дельта: изменённые, удалённые и добавленные-в-индекс файлы против baseline.
   #     `git diff --name-only <rev>` сравнивает РАБОЧЕЕ ДЕРЕВО с ревизией, поэтому покрывает
   #     и staged, и unstaged. Каталог артефактов сессии исключён — он живёт своей жизнью.
   #     `-c core.quotePath=false` — иначе не-ASCII пути печатаются в C-кавычках
   #     (`"\320\272..."`) и не совпадают с реальными именами файлов ниже по пайплайну.
   git -c core.quotePath=false diff --name-only "$base_rev" -- . ':!.claude/sessions/**' > "$tmp_tracked"

   # (2) новые untracked = untracked сейчас МИНУС untracked, записанные в baseline.
   comm -23 \
     <(git ls-files --others --exclude-standard -z | tr '\0' '\n' | sed '/^$/d' \
         | grep -v '^\.claude/sessions/' | LC_ALL=C sort) \
     <(sed -n 's/^untracked //p' "$sdir/prototype_baseline.txt" | LC_ALL=C sort) \
     > "$tmp_new"

   # Fail-closed гард: `-c core.quotePath=false` выше отключает квотирование только
   # не-ASCII байт. Пути, содержащие литеральные `"` или `\`, git квотирует всегда,
   # независимо от `quotePath` — такая строка в списке не совпадает с реальным именем
   # файла, и ни `git checkout`/`git rm`/`rm` ниже не сработают на верном пути. Раз путь
   # закавычен — точечный откат по нему недоказуем, останавливаемся ДО любой операции.
   if grep -q '^"' "$tmp_tracked" "$tmp_new" 2>/dev/null; then
     echo "SDX proto: путь в списке файлов прототипа закавычен git'ом (содержит \" или \\) — точечный откат недоказуем. Откат НЕ выполняется." >&2
     rm -f "$tmp_tracked" "$tmp_new"
     exit 1
   fi

   # (а) tracked: восстановить содержимое baseline; файлы, созданные прототипом и попавшие
   #     в индекс, в baseline отсутствуют — их надо удалить, а не «восстанавливать».
   while IFS= read -r f; do
     [ -z "$f" ] && continue
     if git cat-file -e "$base_rev:$f" 2>/dev/null; then
       git checkout "$base_rev" -- "$f"
     else
       git rm -f --quiet -- "$f"
     fi
   done < "$tmp_tracked"

   # (б) новые untracked: удалить поимённо. НИКАКОГО `git clean -fd`.
   while IFS= read -r f; do
     [ -z "$f" ] && continue
     rm -f -- "$f"
   done < "$tmp_new"

   # (в) прибрать каталоги, опустевшие после (б); непустые каталоги не трогаются.
   while IFS= read -r f; do
     d="$(dirname -- "$f")"
     [ "$d" = "." ] || rmdir -p --ignore-fail-on-non-empty -- "$d" 2>/dev/null || true
   done < "$tmp_new"

   # (г) верификация отката: вне каталога сессии дерево обязано стать чистым.
   leftover="$(git status --porcelain -- . ':!.claude/sessions/**')"
   rm -f "$tmp_tracked" "$tmp_new"
   ```
   - Если `leftover` непуст — откат НЕ объявляй успешным: выведи остаток пользователю дословно. Не приписывай остаток файлам под `.gitignore` — `git status --porcelain` без `--ignored` игнорируемые файлы структурно не показывает, эта причина недостижима. Вероятные причины (называй их прозаически, не додумывая другие): (а) путь был изменён или создан УЖЕ ПОСЛЕ вычисления списка на шаге выше — окно между вычислением `$tmp_tracked`/`$tmp_new` и проверкой (в) не защищено блокировкой; (б) сбой отдельной операции отката — `git checkout`, `git rm` или `rm` для конкретного файла в циклах (а)/(б) не выполнился (правами доступа, занятым файлом и т.п.), а код возврата цикла не проверяется построчно; (в) изменения в путях, исключённых из вычисления списка, — в первую очередь untracked-файлы, поимённо записанные в `prototype_baseline.txt` и потому намеренно исключённые из `$tmp_new` (`comm -23`): они не считаются частью прототипа и остаются как есть, поэтому появляются в `leftover` как `?? path`, даже когда откат полностью успешен. Автоматическая доуборка не выполняется в любом случае — удалять файл без явного решения пользователя опаснее, чем оставить его. Сессия при этом всё равно остаётся на `Execution` с `no_gates == true`; ручная доуборка (или подтверждение, что остаток — ожидаемый файл из причины (в)) — решение пользователя.
   - Независимо от наличия остатка, зафиксируй новую точку восстановления. Захват baseline структурно тот же самый bash-блок, что и на `/sdx:start` для типа `proto` (сверить построчно с `commands/start.md` за вычетом номера попытки: там при первом запуске записывается `1`, здесь — `<N+1>`, где `<N>` — запомненный на шаге 2 `attempt`, номер только что завершённой/отклонённой попытки):
     ```bash
     sdir=".claude/sessions/<id>"
     # Гард безопасности: путь с переводом строки сделал бы построчный формат неоднозначным.
     n_nul=$(git ls-files --others --exclude-standard -z | tr -dc '\0' | wc -c)
     n_ln=$(git ls-files --others --exclude-standard -z | tr '\0' '\n' | sed '/^$/d' | wc -l)
     if [ "$n_nul" != "$n_ln" ]; then
       echo "SDX proto: среди untracked-файлов есть путь с переводом строки — baseline не может быть записан безопасно." >&2
       exit 1
     fi
     {
       printf '# SDX vibe prototype baseline\n'
       printf 'attempt %s\n' "<N+1>"
       printf 'started %s\n' "$(date '+%Y-%m-%d %H:%M:%S')"
       printf 'rev %s\n' "$(git rev-parse HEAD)"
       git ls-files --others --exclude-standard -z | tr '\0' '\n' | sed '/^$/d' | sed 's|^|untracked |'
     } > "$sdir/prototype_baseline.txt"
     git add "$sdir/prototype_baseline.txt" && git commit -m "sdx(<id>): vibe baseline (attempt <N+1>)"
     ```
     Если гард сработал (путь с переводом строки среди untracked) — новый baseline НЕ записывается: сообщи пользователю об ошибке и остановись; попытка `<N+1>` не стартует, пока проблемный путь не будет убран/переименован. Это честный отказ, а не тихая деградация к `git clean`.
   - Затем запиши строку в лог и закоммить её вместе с уже обновлённым baseline (`K` — суммарное число строк, которое было в `$tmp_tracked`+`$tmp_new` до их удаления в шаге (г) выше). Отклонение прототипа — акт категории `[деструктив]` (`PROC-019`): ДО коммита ниже добавь запись в `decisions_log.md` (четыре поля — развилка/вариант/обоснование/этап, см. `sdx/protocol.md` «Журнал решений») и включи файл в тот же `git add`, батчась в этот же коммит, а не отдельным ходом:
     ```bash
     echo "[$(date '+%Y-%m-%d %H:%M:%S')] [CHECKPOINT] Прототип отклонён (попытка <N>), откат по списку из <K> файлов; новая точка — попытка <N+1>" >> "$sdir/session.log"
     git add "$sdir/prototype_baseline.txt" "$sdir/session.log" "$sdir/decisions_log.md" && git commit -m "sdx(<id>): vibe prototype rejected (attempt <N>), baseline reset"
     ```
     (Категория лога — существующая `CHECKPOINT`; отдельная пятая категория не вводится, `STAGE_CHANGE` здесь неверен — `stage` не меняется и `sdx-stage.sh` не вызывается.)
   - Сообщи итог пользователю: сколько файлов восстановлено, сколько удалено, остаток (если есть). Напомни, что сессия осталась на `Execution` (`no_gates == true`) и попытка `<N+1>` может начинаться немедленно.

7. **Ветка «Принять» — передача в легализацию.** Вторым `AskUserQuestion` определи целевой ОБЪЁМ последующей работы (не трек — треков больше нет):

   - сформулируй **рекомендованный** вариант прозаически, тем же суждением, каким сегодня оценивается масштаб задачи на `/sdx:start`: **полный**, если прототип задел публичные контракты, схемы данных или архитектуру, либо получился крупным по объёму диффа; **лёгкий** — в остальных случаях.
   Автоматически, без подтверждения, объём НЕ выбирай — целевой объём легализации это второе, отдельное решение пользователя, а не следствие ответа «Принять». Если `gate_mode == "auto"` — сбрось его в `"interactive"` (`Edit` поля в `session_state.json`) и сообщи об этом пользователю: легализация — по определению новое суждение о масштабе, исходный дефолт, принятый (если принимался) при самом `/sdx:start proto`, к этому решению не относится (ADR-014).

      ```bash
        > "$tmp_new"
      ```
      Это единственный допустимый источник «что было сделано» — не память диалога и не `git status`.

   2. **Spec-after реверс-инжиниринг — ДО коммитов.** Гейты `sdx-stage.sh` проверяют артефакты на диске, а не в git, поэтому порядок «сначала артефакты, потом коммиты» полностью легален:
      - целевой объём **лёгкий** — `change_note.md` создаётся **инлайн основной сессией** (симметрия с лёгким объёмом обычной сессии, где `Discovery`/планировочные этапы идут инлайн, без `architect`). Содержимое: что и зачем сделано (переформулировано как требование, а не как пересказ диффа), перечень затронутых файлов, сознательно отложенное. Если объём прототипа таков, что инлайн реверс-инжиниринг честно не помещается, — это сигнал, что целевой объём **полный**, а не повод писать тонкий `change_note.md`;
      - целевой объём **полный** — последовательно, через Task: `architect` → `context_report.md` (ретроспективный: что прототип задел в кодовой базе, какие интеграционные точки и допущения принял де-факто); `ba` → `SPEC.md` (Delta-формат, `[ADDED]`); `architect` → `DESIGN.md`; `lead-dev` → `PLAN.md` (задачи вида «покрыть тестами / довести до контракта / убрать срезанные углы», не «реализовать с нуля»). Всем четверым на вход даются ПУТИ + команда получения диффа, а не тело диффа (экономия токенов, ADR-005), кроме случая, когда дифф мал и передать его дешевле.

   3. **Первый коммит кода (REQ-VIBE-7) и пост-проверка, что он состоялся.** Между п.1 и этой точкой пройдена серия `Task`-вызовов субагентов (п.2): shell-сессия, в которой п.1 вычислил `$base_rev`/`$tmp_tracked`/`$tmp_new`, к этому моменту гарантированно завершена — ни переменные, ни временные файлы `mktemp` больше не существуют. Весь блок ниже — **один непрерывный bash-блок**, исполняемый одним ходом: сначала пересчёт списка (дословно тот же фрагмент, что и в п.1, построчно совпадающий с шагом 3 выше), затем объединение обоих списков в один (`$tmp_all` — ровно те файлы, за которые эта проверка отвечает), затем коммит только по нему (никогда `git add -A`), затем обязательная пост-проверка ДО снятия `no_gates` (п.5) того, что коммит действительно состоялся. Учти: пустой `$tmp_all` (прототип с последнего baseline ничего не изменил) — легитимный случай, а не ошибка: `git add`/`git commit` в этой ветке вовсе не вызываются (иначе `git add --` без аргументов вернул бы `0`, ничего не застейджив, а `git commit` упал бы «nothing to commit»), `commit_rc` считается `0` явно. При непустом `$tmp_all` единственный настоящий симптом отказа — после коммита хотя бы один файл ИЗ ЭТОГО списка остаётся с незакоммиченными изменениями; посторонние untracked-файлы пользователя вне списка (включая записанные в baseline и потому исключённые из `$tmp_new`) проверке не подлежат — REQ-VIBE-7 их не касается, и их присутствие не должно обрывать легализацию. Сразу после пересчёта списка (до объединения в `$tmp_all`) стоит fail-closed гард: `-c core.quotePath=false` в каноническом фрагменте отключает квотирование только не-ASCII байт, а пути с литеральным `"` или `\` git закавычивает всегда — такая строка в списке не совпадает с реальным именем файла, дальнейшие поимённые операции по ней недоказуемы, и легализация останавливается (`no_gates` НЕ снимается) прежде, чем что-либо будет закоммичено.
      ```bash
      sdir=".claude/sessions/<id>"
      base_rev="$(awk '$1=="rev"{print $2; exit}' "$sdir/prototype_baseline.txt")"
      git rev-parse --verify --quiet "${base_rev}^{commit}" >/dev/null || {
        echo "SDX proto: baseline-ревизия ${base_rev} не найдена — точечный откат недоказуем." >&2; exit 1; }

      tmp_tracked="$(mktemp)"; tmp_new="$(mktemp)"

      # (1) tracked-дельта: изменённые, удалённые и добавленные-в-индекс файлы против baseline.
      #     `git diff --name-only <rev>` сравнивает РАБОЧЕЕ ДЕРЕВО с ревизией, поэтому покрывает
      #     и staged, и unstaged. Каталог артефактов сессии исключён — он живёт своей жизнью.
      #     `-c core.quotePath=false` — иначе не-ASCII пути печатаются в C-кавычках
      #     (`"\320\272..."`) и не совпадают с реальными именами файлов ниже по пайплайну.
      git -c core.quotePath=false diff --name-only "$base_rev" -- . ':!.claude/sessions/**' > "$tmp_tracked"

      # (2) новые untracked = untracked сейчас МИНУС untracked, записанные в baseline.
      comm -23 \
        <(git ls-files --others --exclude-standard -z | tr '\0' '\n' | sed '/^$/d' \
            | grep -v '^\.claude/sessions/' | LC_ALL=C sort) \
        <(sed -n 's/^untracked //p' "$sdir/prototype_baseline.txt" | LC_ALL=C sort) \
        > "$tmp_new"

      # Fail-closed гард: `-c core.quotePath=false` выше отключает квотирование ТОЛЬКО
      # не-ASCII байт. Пути, содержащие литеральные `"` или `\`, git квотирует всегда,
      # независимо от `quotePath` (например `"file\".txt"` печатается как
      # `"file\"\".txt"`), поэтому такая строка не совпадает с реальным именем файла и
      # ни одна из операций ниже (`git add`, `git status`) не будет ссылаться на верный
      # путь. Раз путь закавычен — дальнейшая работа с ним недоказуема, останавливаемся.
      if grep -q '^"' "$tmp_tracked" "$tmp_new" 2>/dev/null; then
        echo "SDX proto: путь в списке файлов прототипа закавычен git'ом (содержит \" или \\) — дальнейшие операции недоказуемы. no_gates НЕ снимается." >&2
        rm -f "$tmp_tracked" "$tmp_new"
        exit 1
      fi

      # Список, за который отвечает пост-проверка ниже, — и только он. Посторонние
      # untracked-файлы пользователя (в т.ч. записанные в baseline и потому исключённые
      # из $tmp_new выше) в этот список не входят и не обязаны быть чистыми.
      tmp_all="$(mktemp)"
      cat "$tmp_tracked" "$tmp_new" | sed '/^$/d' | LC_ALL=C sort -u > "$tmp_all"

      if [ -s "$tmp_all" ]; then
        # Построчное POSIX-чтение вместо `xargs -d '\n'` (GNU-специфичный флаг `-d`,
        # отсутствует на macOS/BSD xargs) и вместо `$(cat "$tmp_all")` — тот и другой
        # вариант ломается на путях с пробелами word-splitting'ом.
        while IFS= read -r f; do [ -n "$f" ] || continue; git add -- "$f"; done < "$tmp_all"
        git commit -m "sdx(<id>): vibe prototype code (legalized)"
        commit_rc=$?
      else
        # Пустой список — коммитить нечего (не ошибка, см. пояснение выше): git add/commit
        # не вызываются вовсе.
        commit_rc=0
      fi

      # Пост-проверка REQ-VIBE-7: коммит кода обязан состояться ДО снятия no_gates. Критерий —
      # ФАКТИЧЕСКОЕ СОСТОЯНИЕ файлов списка (leftover_code), а не код возврата `git commit`:
      # `git add --` без аргументов молча возвращает 0, поэтому одного кода возврата мало;
      # а ненулевой `commit_rc` при пустом остатке — легитимный случай, а не отказ (например,
      # код прототипа уже был закоммичен пользователем вручную во время `Execution`: `git add`
      # не застейджил ничего нового, `git commit` упал с «nothing to commit», но сами файлы
      # списка уже чисты относительно `HEAD` — REQ-VIBE-7 фактически выполнен). Проверяем
      # РОВНО ВЫЧИСЛЕННЫЙ СПИСОК ($tmp_all), а не всё рабочее дерево — иначе проверка ложно
      # спотыкается о посторонние untracked-файлы пользователя, зафиксированные в baseline.
      # Проверка идёт по одному точному пути за раз (тот же построчный POSIX-цикл, что и у
      # `git add` выше, вместо GNU-специфичного `xargs -d '\n'`) — это корректно независимо
      # от квотирования, поскольку нас интересует лишь непустота вывода на каждый файл.
      if [ -s "$tmp_all" ]; then
        leftover_code=""
        while IFS= read -r f; do
          [ -n "$f" ] || continue
          out="$(git status --porcelain -- "$f")"
          [ -n "$out" ] && leftover_code="${leftover_code}${out}
"
        done < "$tmp_all"
      else
        leftover_code=""
      fi
      rm -f "$tmp_tracked" "$tmp_new" "$tmp_all"

      if [ -n "$leftover_code" ]; then
        echo "SDX proto: коммит кода прототипа (REQ-VIBE-7) не состоялся — no_gates НЕ снимается." >&2
        printf '%s\n' "$leftover_code" >&2
        exit 1
      fi
      ```
      Запрет `git add -A`/`git add .` симметричен запрету слепого авто-коммита в `switch.md` и служит той же цели: посторонние untracked-файлы пользователя не должны попасть в ветку сессии. **Если пост-проверка остановила выполнение (код `1`) — ОСТАНОВИСЬ.** Не переходи ни к п.4 (артефакты), ни тем более к п.5 (снятие `no_gates`): флаг `no_gates` в `session_state.json` в этой точке ещё не тронут, рассинхронизации нет. Сообщи пользователю остаток `git status` (по вычисленному списку) дословно и предложи разобраться вручную (`git status`, `git diff`) перед повторным вызовом легализации.

   4. **Второй коммит — артефакты реверс-инжиниринга:**
      ```bash
      git add .claude/sessions/<id> && git commit -m "sdx(<id>): legalize prototype — spec-after artifacts"
      ```
      Порядок «код → артефакты» выбран для читаемости `git log`: первый коммит — точное замыкание прототипа (`git show` даёт ровно его), второй — выведенный из него контракт. Для `reviewer` порядок безразличен: `verify.md` шаг 4 берёт дифф всей ветки против основной.

   5. **Снятие режима «без гейтов» — три под-шага (REQ-FLAG-4, одноразовость).** Практическое упрощение по сравнению со старым механизмом смены трека: подшаг «откат к прежнему значению при отказе guard'а» отсутствует как класс — предмета нет (нет evidence-guard'а, который мог бы отказать; см. (а) ниже), а снятие `no_gates` — операция над ДРУГИМ полем, чем `stage`, и не участвует в одной транзакции с вызовом `next`.
      1. Целевой `stage` — не «ближайший активный этап нового трека», а прямой вызов:
         ```bash
         bash "${CLAUDE_PLUGIN_ROOT}/sdx/hooks/sdx-stage.sh" next "<id>" --to "Execution"
         ```
         Он тривиально безопасен и не требует НИКАКОЙ evidence-проверки по совершенно конкретной причине: сессия с `no_gates == true` ВСЕГДА находится на `stage == "Execution"` (REQ-SCALE-5) — значит `--to "Execution"` целится в СВОЙ ЖЕ текущий этап (`idx_target == idx_current`), что по контракту `next --to` (см. `sdx/hooks/sdx-stage.sh`) — буквальный **no-op**: файл `stage` не трогается вообще, писать нечего, кроме последующего снятия `no_gates`. Артефакты реверс-инжиниринга к этому моменту уже созданы шагом 2 выше — именно они станут доказательством гейта СЛЕДУЮЩЕГО, уже обычного вызова `next` (без `--to`), когда сессия продолжит путь `Execution → Verification → Closeout` штатно.
      2. **Снятие `no_gates` (REQ-FLAG-4, одноразовость)** — прямой `Edit` поля `no_gates: true → false` в `session_state.json` (легитимный путь — поле не `stage`, и в любом случае deny-хука, который мог бы это заблокировать, больше не существует) — ОДИН РАЗ, ДО следующего вызова `next`, потому что приоритет-0 проверка REQ-LEGAL-1 в `cmd_next` иначе продолжит возвращать `OK no-op Execution` бесконечно. Легализация прототипа — акт категории `[деструктив]` (`PROC-019`, симметрично отклонению на шаге 6): ДО коммита ниже добавь запись в `decisions_log.md` (четыре поля, см. `sdx/protocol.md` «Журнал решений»). Закоммить эту правку вместе с логом и журналом решений одним ходом:
         ```bash
         echo "[$(date '+%Y-%m-%d %H:%M:%S')] [STAGE_CHANGE] Легализация прототипа: снятие no_gates" >> .claude/sessions/<id>/session.log \
           && git add .claude/sessions/<id>/session_state.json .claude/sessions/<id>/session.log .claude/sessions/<id>/decisions_log.md \
           && git commit -m "sdx(<id>): legalize prototype — drop no_gates"
         ```
         Повторная установка `no_gates: true` в ЭТОЙ ЖЕ сессии запрещена прозаически текстом этой команды и `commands/next.md` (REQ-FLAG-4) — тот же класс trade-off, что и сегодняшний запрет обратного входа в режим прототипирования. Не предлагай её пользователю ни в каком виде.
      3. Дальше — обычный `next` без `--to`: `Execution` (доводка, `developer`; с этого момента `stop-gate` снова видит стандартное `Execution` без прозрачности `no_gates`, и норма инкрементальных коммитов действует без исключений) → `Verification` (`qa` + fresh-eyes `reviewer`) → `Closeout` (`/sdx:archive`), уже штатным путём целевого объёма.

Граничные случаи (fail-closed по построению — ничего из перечисленного не додумывай самостоятельно):
- **Прототип успел закоммитить код** (нарушение REQ-VIBE-3, например ручным `git commit` пользователя) — `git diff --name-only "$base_rev"` всё равно перечислит такие файлы (сравнение с ревизией, а не с индексом), и откат восстановит их содержимое, но сами коммиты останутся в истории ветки. Сообщи об этом честно: «откат восстановил содержимое файлов, но коммиты `<sha...>` остались в истории ветки — при необходимости используй `git reset` вручную». Автоматический `git reset` НЕ выполняй — переписывание истории вне объёма этой команды.
- **Прототип удалил tracked-файл** — попадает в `$tmp_tracked`, восстанавливается веткой `git checkout "$base_rev" -- "$f"` в шаге (а). Отдельной обработки не требует.
- **Прототип создал файл и сделал `git add`** — не виден `git ls-files --others`, но виден `git diff --name-only "$base_rev"`; поскольку в baseline-ревизии его нет, срабатывает ветка `git rm -f` в шаге (а).
- **Повторные попытки** — `attempt` инкрементируется, новый baseline перезаписывает старый; история старых baseline доступна через `git log -p -- prototype_baseline.txt`, отдельный архив попыток не ведётся сознательно.
