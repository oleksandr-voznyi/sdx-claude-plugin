---
description: Просмотр статуса текущей активной сессии SDX.
---

Ты выполняешь роль Session Manager. Твоя задача — предоставить отчет о текущем состоянии активной сессии. Это **чисто читающая** операция: НЕ пиши в лог и не меняй состояние (просмотр статуса не должен мутировать сессию).

Алгоритм:
1. Определи текущую сессию по активной git-ветке (`git branch --show-current`, ветки вида `sdx/<id>`) или по содержимому `.claude/sessions/`.
2. Считай `.claude/sessions/<id>/session_state.json`.
3. Выведи пользователю:
   - **Session ID**, **Current Stage**, **No-code** / **No-gates** (значения флагов `no_code`/`no_gates` из state — режим сессии выражается ими, не полем `track`, которого в схеме больше нет), **Status**.
   - **Artifacts**: текущий состав файлов сессии — из `git status`/листинга папки сессии (не из лога).
   - **Progress**: % выполнения из `PLAN.md` (греп чек-боксов `- [ ]`/`- [x]`), если он есть.
   - При `no_gates == true` дополнительно выведи номер текущей попытки (`attempt` из `prototype_baseline.txt`) и подсказку `/sdx:proto`.
4. **(факультативно) Активные сессии.** Дополнительно выведи листинг всех активных сессий в проекте через `git branch --list 'sdx/*'` — каждая ветка `sdx/<id>` соответствует отдельной активной (незаархивированной) сессии. Это чисто читающий шаг, не влияющий на текущую сессию.
5. **Здоровье enforcement** (REQ-HEALTH-1/2/3). Чисто читающий шаг: НЕ запускай `selftest.sh` повторно ни при каких условиях — ни безусловно, ни по какому-либо триггеру внутри этого шага; не пиши и не создавай ничего в `.claude/sdx/` (в частности, не трогай `.claude/sdx/.cache/`).
   - Структурные факты — вычисляй заново при каждом вызове (дёшево, доверие кэшу здесь не даёт экономии и создаёт риск устаревания):
     - `jq`: `command -v jq >/dev/null 2>&1 && echo present || echo MISSING`
     - `prod-guard.conf`: `[ -s .claude/sdx/prod-guard.conf ] && echo "present, non-empty" || echo "missing or empty"`
     - `verify-cmd.sh`: `[ -x .claude/sdx/verify-cmd.sh ] && echo "present, executable" || { [ -f .claude/sdx/verify-cmd.sh ] && echo "present, NOT executable" || echo "missing"; }`
     - соответствие ветки: сравни `git branch --show-current` с `sdx/<session_id>` из `session_state.json`.
   - Результат последнего self-test — читай ТОЛЬКО `.claude/sdx/.cache/selftest.json` (никогда не пересчитывай и не запускай `selftest.sh` заново):
     - Если файла нет — выведи «self-test ещё не выполнялся».
     - Иначе выведи `selftest_status` (`ok`/`degraded`/`broken`), результат по каждому хуку (`preflight`/`prod_guard`/`stop_gate`: `pass`/`fail`/`skip`), `duration_ms`/`budget_exceeded`, и явно возраст `ts` относительно текущего времени (например: «прогонялся N назад — статус может быть устаревшим до следующего SessionStart: если позже правились конфиги слоя, а также ВСЕГДА, если правились сами хуки, — их содержимое в отпечаток кэша не входит»), чтобы пользователь не спутал «закэшировано» с «проверено прямо сейчас».
   - Формулировки: это диагностика, не гейт. Провал self-test — только видимость человеку; он ничего не решает и никак не связан с автономией CLI-сессии или доступными классами риска — этих механизмов в репозитории сегодня нет. Ссылайся на `FEAT-010`/`FEAT-006`/`FEAT-004` как на будущие точки подключения реального потребителя.
