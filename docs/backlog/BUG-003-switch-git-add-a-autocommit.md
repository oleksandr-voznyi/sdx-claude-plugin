# BUG-003. `/sdx:switch` делает `git add -A` с авто-коммитом

## Суть
Слепой `git add -A && git commit` перед checkout закоммитит в ветку сессии всё,
что лежало в дереве (мусор, потенциально секреты), с шумным сообщением. Не обработаны
конфликтные случаи (checkout невозможен, та же ветка).

## Рекомендация
Минимум — `git stash push` вместо авто-коммита; лучше — перевести параллельные сессии на
`git worktree` (одна сессия = свой worktree): убирает класс проблемы «переключение через
общее дерево». Хуки уже worktree-совместимы (сессия по ветке).

## Решения груминга
*Сессия `grooming-sdx-2-0-20260831`.*

**Повышена до `high`, перенесена из волны 8 в волну 1.** Приоритет поднят по существу дефекта:
слепой `git add -A` с авто-коммитом способен затянуть в коммит посторонние файлы, включая секреты,
— это деструктивное поведение в команде, которая выглядит навигационной.

Волна 1 — потому что `PROC-019` в той же волне переписывает понятие сессии в понятие прогона и
вводит `/sdx:resume`; поверхность переключения между сессиями перестраивается там же, и чинить её
дважды не нужно.

**Рекомендация выше частично устарела:** предложение «перевести параллельные сессии на
`git worktree`» противоречит `ADR-012`, отменившему worktree в пользу ветки в текущем дереве.
Актуальны остаются `git stash push` вместо авто-коммита и обработка конфликтных случаев; вариант с
worktree при исполнении не рассматривать без пересмотра `ADR-012`.

## Резолюция
*Закрыта 2026-09-01 сверкой записи с фактическим кодом, вне сессии.*

**Дефект уже исправлен и был исправлен задолго до этой проверки.** Слепой
`git add -A && git commit -m "sdx: auto-save session before switch"` жил в `switch.md`
с первого коммита фреймворка и снят коммитом `1ade803` («in-place branch session model
(ADR-012) — drop worktree, single CLI») от 2026-07-05 — **через четыре дня после аудита
`audit-2026-07-01`, породившего эту запись**. Отмена worktree потребовала переписать
переключение сессий целиком, и авто-коммит исчез попутно, не будучи целью той поставки;
запись об этом никто не закрыл.

Текущее состояние `commands/switch.md` покрывает обе части «Сути»:
- авто-коммит запрещён явной нормой в преамбуле команды («Слепой авто-коммит ЗАПРЕЩЁН
  (ядро REQ-WT-2): НИКАКИХ `git add -A && git commit` от имени пользователя»);
- случай «checkout невозможен» обработан гардом чистого дерева (шаг 2) с направлением на
  инкрементальный коммит или `git stash`, плюс проверкой существования ветки (шаг 1).

**Остаток, признанный несущественным:** случай «целевая ветка совпадает с текущей» отдельной
ветвью не обработан. `git checkout` на текущую ветку — no-op без побочных эффектов, поэтому
поведение корректно и без явной проверки; отдельная запись под это не заводится.

**Рекомендация про `git worktree` не исполнена и исполнена не будет** — она противоречит
`ADR-012`, что уже зафиксировал груминг `grooming-sdx-2-0-20260831`.

Процессная причина, по которой запись дожила до волны 1 в статусе `high`, вынесена
отдельно: [PROC-026](PROC-026-grooming-without-code-verification.md).
