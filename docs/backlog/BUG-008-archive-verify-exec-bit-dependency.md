# BUG-008. `archive-verify.sh` — единственная точка, зависящая от бита выполнения; ложный FAIL Closeout

## Суть
`/sdx:archive` на шаге 7 выдаёт ложный отказ, отменяющий завершение Closeout:

```
archive-verify.sh: line 13: .../sdx/hooks/lib/default-branch.sh: Permission denied
fatal: malformed object name
[FAIL] ветка sdx/<id> не слита в .
[ABORT] Closeout не завершён — устраните FAIL и повторите.
```

Ветка при этом слита, дерево чистое, каталог сессии удалён — все три инварианта фактически
выполняются. Сообщение уводит в неверную сторону: пользователь идёт проверять мёрж, которого
проблема не касается. Видимый след первопричины — «в `.`» в тексте FAIL: вместо имени основной
ветки подставлена пустая строка.

**Механизм.** `archive-verify.sh:13` резолвит основную ветку, *исполняя* lib-скрипт:

```bash
def="$("$here/lib/default-branch.sh" "$proj")"      # ADR-010: no hardcoded 'main'
```

Исполнение требует бита `x`. Если в среде установки бит снят, подстановка возвращает пустую
строку; `set -uo pipefail` без `-e` (строка 8) выполнение не прерывает, и дальше пустой `$def`
уходит в `git merge-base` / `git branch --merged`, давая `malformed object name` и ложный провал
инварианта 5.

**Первопричина — не в исходнике.** В репозитории режимы корректны:
`git ls-files -s sdx/hooks/lib/default-branch.sh` → `100755`. Бит срезается при
установке/синхронизации плагина: в наблюдённой среде (`~/.claude/remote/plugins/<hash>/`,
marketplace-источник с `autoUpdate: true`) все 18 `sdx/hooks/**/*.sh` лежат с правами `0600`.

**Почему задет ровно один скрипт.** Это единственное место продакшн-кода, исполняющее
lib-скрипт. Остальное к биту `x` иммунно по построению:

| Точка | Способ вызова | Нужен бит `x` |
|-------|---------------|---------------|
| `archive-verify.sh:13` → `lib/default-branch.sh` | исполнение | **да — ломается** |
| `stage-gate.sh:9`, `stop-gate.sh:8`, `stage-write-guard.sh:18` → `lib/resolve-session.sh` | `. "$here/lib/…"` (source) | нет |
| `commands/archive.md:70`, `commands/verify.md:25` → `lib/default-branch.sh` | `bash "${CLAUDE_PLUGIN_ROOT}/…"` | нет |
| Все прочие вызовы хуков из команд `/sdx:*` | `bash <путь>` | нет |

Поэтому дефект не проявляется больше нигде, и его легко принять за проблему мёржа: остальной
enforcement-слой в той же среде работает штатно.

Смежно с [BUG-006](BUG-006-stage-gate-windows-backslash-paths.md) — тот же класс: хук корректен
по логике, но ломается о свойство среды развёртывания, а симптом выглядит как содержательный
отказ. Смежно с [DEBT-010](DEBT-010-silent-hook-degradation-invisible.md) (тихая деградация хуков
не видна пользователю): здесь деградация не тихая, но её сообщение дезинформирует.

## Рекомендация
1. **Основное** — снять зависимость от бита выполнения (одна строка, `archive-verify.sh:13`):

   ```bash
   def="$(bash "$here/lib/default-branch.sh" "$proj")"
   ```

   Это приводит вызов к той же форме, что уже используется в `commands/archive.md:70` и
   `commands/verify.md:25`, и делает скрипт независимым от того, как развёрнут плагин. Дешевле и
   надёжнее, чем требовать сохранения режимов от всех возможных установщиков.

2. **Не отправлять пустой `$def` в git молча.** Даже с фиксом п. 1 стоит проверить результат
   резолва и отказывать явно (`[FAIL] не удалось определить основную ветку`) — сейчас первопричина
   видна только по `malformed object name` в stderr. Ср. DEBT-010.

3. **Тест.** Прогнать `sdx/hooks/test-archive-verify.sh` в окружении со снятым битом `x` у
   `lib/*.sh` — сценарий должен быть красным без фикса п. 1. Заодно выровнять режимы самих тестов:
   в репозитории `test-prod-guard.sh`, `test-stage-gate.sh`, `test-stage-write-guard.sh`,
   `test-stop-gate.sh` имеют `100644`, остальные — `100755`; расхождение ни на что не влияет (их
   зовут через `bash`), но маскирует подобные находки при просмотре режимов.

4. **Отдельно от кода** — если срезание режимов при синхронизации плагина является дефектом
   установщика, а не намеренным поведением, это стоит зарепортить туда; запись закрывается
   независимо от того исхода, поскольку п. 1 делает плагин устойчивым в любом случае.

**Обходной путь до фикса:** `chmod +x <plugin-root>/sdx/hooks/lib/*.sh` — локальный и временный,
при `autoUpdate: true` очередная синхронизация, скорее всего, снова срежет бит.
