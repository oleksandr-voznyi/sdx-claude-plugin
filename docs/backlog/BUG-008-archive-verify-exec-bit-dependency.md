# BUG-008. Зависимость от бита выполнения: ложный FAIL Closeout + тихая смерть enforcement-слоя

## Суть
`/sdx:archive` на шаге 7 выдаёт ложный отказ, отменяющий завершение Closeout:

```
archive-verify.sh: line 13: .../sdx/hooks/lib/default-branch.sh: Permission denied
fatal: malformed object name
[FAIL] ветка sdx/<id> не слита в .
[ABORT] Closeout не завершён — устраните FAIL и повторите.
```

Ветка при этом слита, дерево чистое, каталог сессии удалён — все три инварианта фактически
выполняются. Сообщение уводит в неверную сторону: пользователь идёт проверять мёрж, которого
проблема не касается. Видимый след первопричины — «в `.`» в тексте FAIL: вместо имени основной
ветки подставлена пустая строка.

**Механизм.** `archive-verify.sh:13` резолвит основную ветку, *исполняя* lib-скрипт:

```bash
def="$("$here/lib/default-branch.sh" "$proj")"      # ADR-010: no hardcoded 'main'
```

Исполнение требует бита `x`. Если в среде установки бит снят, подстановка возвращает пустую
строку; `set -uo pipefail` без `-e` (строка 8) выполнение не прерывает, и дальше пустой `$def`
уходит в `git merge-base` / `git branch --merged`, давая `malformed object name` и ложный провал
инварианта 5.

**Первопричина — не в исходнике.** В репозитории режимы корректны:
`git ls-files -s sdx/hooks/lib/default-branch.sh` → `100755`. Бит срезается при
установке/синхронизации плагина: в наблюдённой среде (`~/.claude/remote/plugins/<hash>/`,
marketplace-источник с `autoUpdate: true`) все 18 `sdx/hooks/**/*.sh` лежат с правами `0600`.

**Масштаб зависимости — шесть точек, а не одна.** Полевой репорт утверждал, что
`archive-verify.sh:13` — единственное место, требующее бита `x`; проверка при верификации фикса
это опровергла. Помимо него прямым исполнением вызываются все пять регистраций боевой проводки
`hooks/hooks.json`:

| Точка | Способ вызова | Нужен бит `x` |
|-------|---------------|---------------|
| `archive-verify.sh:13` → `lib/default-branch.sh` | исполнение | **да — ломается** |
| `hooks/hooks.json` → `preflight.sh`, `stage-gate.sh`, `stage-write-guard.sh`, `prod-guard.sh`, `stop-gate.sh` | исполнение (`"${CLAUDE_PLUGIN_ROOT}"/sdx/hooks/<x>.sh`) | **да — ломаются** |
| `stage-gate.sh:9`, `stop-gate.sh:8`, `stage-write-guard.sh:18` → `lib/resolve-session.sh` | `. "$here/lib/…"` (source) | нет |
| `commands/archive.md:70`, `commands/verify.md:25` → `lib/default-branch.sh` | `bash "${CLAUDE_PLUGIN_ROOT}/…"` | нет |
| Все прочие вызовы хуков из команд `/sdx:*` | `bash <путь>` | нет |

Проверено эмпирически: копия `stage-gate.sh` с правами `0600`, запущенная в форме `hooks.json`,
даёт `Permission denied` и `exit 126`.

**Асимметрия видимости — почему репорт пришёл именно про Closeout.** Отказ `archive-verify.sh`
громкий: он отменяет завершение сессии и предъявляет пользователю текст. Отказ hook-скрипта с
`exit 126` пользователю не виден вовсе — детерминированный слой (SessionStart/PreToolUse/Stop)
просто перестаёт срабатывать, и сессия выглядит нормальной. Поэтому вывод репорта «остальной
enforcement-слой в той же среде работает штатно» был не наблюдением, а следствием невидимости
отказа — ровно класс DEBT-010. В среде с `0600` на всех 18 файлах не работает ничего из слоя.

Смежно с [BUG-006](BUG-006-stage-gate-windows-backslash-paths.md) — тот же класс: хук корректен
по логике, но ломается о свойство среды развёртывания, а симптом выглядит как содержательный
отказ. Смежно с [DEBT-010](DEBT-010-silent-hook-degradation-invisible.md) (тихая деградация хуков
не видна пользователю): на `archive-verify.sh` деградация не тихая, но её сообщение
дезинформирует; на пяти хуках проводки — тихая ровно в смысле DEBT-010.

## Рекомендация
1. **Основное** — снять зависимость от бита выполнения (одна строка, `archive-verify.sh:13`):

   ```bash
   def="$(bash "$here/lib/default-branch.sh" "$proj")"
   ```

   Это приводит вызов к той же форме, что уже используется в `commands/archive.md:70` и
   `commands/verify.md:25`, и делает скрипт независимым от того, как развёрнут плагин. Дешевле и
   надёжнее, чем требовать сохранения режимов от всех возможных установщиков.

2. **Не отправлять пустой `$def` в git молча.** Даже с фиксом п. 1 стоит проверить результат
   резолва и отказывать явно (`[FAIL] не удалось определить основную ветку`) — сейчас первопричина
   видна только по `malformed object name` в stderr. Ср. DEBT-010.

3. **Тест.** Прогнать `sdx/hooks/test-archive-verify.sh` в окружении со снятым битом `x` у
   `lib/*.sh` — сценарий должен быть красным без фикса п. 1. Заодно выровнять режимы самих тестов:
   в репозитории `test-prod-guard.sh`, `test-stage-gate.sh`, `test-stage-write-guard.sh`,
   `test-stop-gate.sh` имеют `100644`, остальные — `100755`; расхождение ни на что не влияет (их
   зовут через `bash`), но маскирует подобные находки при просмотре режимов.

4. **Проводка `hooks/hooks.json`** (добавлено по находке верификации, а не из исходного репорта) —
   перевести все пять регистраций на `bash "${CLAUDE_PLUGIN_ROOT}"/sdx/hooks/<x>.sh` и закрепить
   инвариант формы вызова тестом, иначе фикс п. 1 чинит одну точку из шести.

5. **Отдельно от кода** — если срезание режимов при синхронизации плагина является дефектом
   установщика, а не намеренным поведением, это стоит зарепортить туда; запись закрывается
   независимо от того исхода, поскольку пп. 1 и 4 делают плагин устойчивым в любом случае.

**Обходной путь до фикса:** `chmod +x <plugin-root>/sdx/hooks/*.sh <plugin-root>/sdx/hooks/lib/*.sh`
— локальный и временный, при `autoUpdate: true` очередная синхронизация, скорее всего, снова
срежет бит.

## Резолюция

Закрыто сессией `fix-archive-verify-exec-bit-20260725` (трек `patch`, 2026-07-25). Устранены все
шесть точек зависимости от бита выполнения:

- `sdx/hooks/archive-verify.sh:13` — резолвер вызывается через `bash <путь>`; добавлен явный
  отказ `[FAIL] не удалось определить основную ветку` до всех проверок и до деструктива, так что
  пустой ref больше не уходит в git под видом «ветка не слита».
- `hooks/hooks.json` — все пять регистраций (`preflight`, `stage-gate`, `stage-write-guard`,
  `prod-guard`, `stop-gate`) переведены на `bash "${CLAUDE_PLUGIN_ROOT}"/…`. Эта часть в исходном
  репорте отсутствовала и была найдена fresh-eyes ревью на верификации: первая редакция фикса
  чинила одну точку из шести, а пять остальных умирали молча с `exit 126`.
- Инвариант формы вызова назван в `sdx/protocol.md` («Enforcement-слой») и enforced новым сьютом
  `sdx/hooks/test-hook-wiring.sh` — для проводки `hooks.json` это гарантия, для вызовов из
  прозаических команд `/sdx:*` остаётся конвенция текста.
- Регрессия: `test-archive-verify.sh` 24/24 (два новых сценария подтверждены красными на
  до-фиксовой версии), полный сьют 10/10.

Отложено отдельными записями: [DEBT-026](DEBT-026-stop-gate-verify-cmd-exec-bit.md) (`stop-gate`
определяет тест-команду по биту `x` — смена семантики, не формы вызова) и
[DEBT-027](DEBT-027-legacy-hook-paths-in-permanent-docs.md) (легаси-пути `.claude/sdx/hooks/`
в постоянных документах).

**Условие получения эффекта:** правка `hooks/hooks.json` действует только после
`/plugin marketplace update sdx` — рантайм исполняет установленную копию плагина.
