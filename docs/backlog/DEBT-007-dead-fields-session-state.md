# DEBT-007. Мёртвые поля в `session_state.json`

## Суть
`artifacts` и `history` объявлены в схеме протокола, но ни одна команда их не
пишет/не читает (состав артефактов по ADR-005 выводится из git). `status`
(`draft|review|approved|executing`) упоминается один раз — в гейте Business Spec.

## Рекомендация
Убрать `artifacts`/`history` из схемы; `status` либо специфицировать
(когда какие переходы), либо заменить на реально нужное гейтам — например
`approvals: {spec, design, warn_ack}`.

## Резолюция
Отложено грумингом `grooming-sdx-2-0-20260831` в ожидании волны 2 (`PROC-012`/`PROC-013`):
мёртвые поля `session_state.json` исчезают вместе с переписыванием состояния под прогон (`PROC-019`). Чинить запись отдельной сессией — работа, которая будет выброшена сносом.

Отсрочка защищена тем, что линия 1.7.0 заморожена, тегирована и содержит дефект как есть:
у пользователей 1.7.0 поведение не меняется, а на 2.0 запись либо исчезает вместе с предметом,
либо возвращается в `open`, если снос будет отклонён или сокращён.
