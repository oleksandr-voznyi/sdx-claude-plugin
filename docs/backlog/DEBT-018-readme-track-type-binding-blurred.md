# DEBT-018. Столбец «Типы сессий» в README стирает жёсткость привязки типа к треку `doc`

## Суть
`README.md` и `README.en.md` показывают типы сессий столбцом таблицы одинаково для всех
четырёх треков. Из такой подачи не видно ключевого различия, зафиксированного в REQ-DOC-7:
для `patch`/`standard`/`full` тип — лишь стартовая гипотеза, а трек выбирается триажем и
адаптивен; для `doc` связь `type → track` жёсткая 1:1 и без диалога.

## Рекомендация
Полстроки в оба README: пометить, что четыре типа трека `doc` привязаны к нему
безусловно, в отличие от триажа остальных треков.

## Резолюция
Закрыто сессией `fix-track-consistency-20260722` (трек `patch`). В `README.md` и `README.en.md`
строка `doc` таблицы треков помечена «(жёстко привязаны, без триажа)» / «(rigidly bound, no
triage)» — симметрично уже размеченной строке `vibe`. Сверх исходной «полустроки» под таблицей
добавлена поясняющая блок-цитата, явно противопоставляющая триаж (`patch`/`standard`/`full`) и
жёсткую 1:1-привязку (`doc`/`vibe`) — прямее закрывает суть REQ-DOC-7. Расширение объёма
относительно исходной формулировки поймано fresh-eyes ревью как WARN и квитировано пользователем
дозаписью контракта `change_note.md` (interactive), в отдельную запись бэклога не выделялось.

Верификация: fresh-eyes PASS, 0 FAIL, 1 WARN (квитирован).
