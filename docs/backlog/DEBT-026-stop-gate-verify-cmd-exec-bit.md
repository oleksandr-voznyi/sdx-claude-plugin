# DEBT-026. `stop-gate` определяет тест-команду по биту выполнения — потеря бита молча снимает тест-пол

## Суть
`sdx/hooks/stop-gate.sh:34` выбирает per-project тест-команду проверкой бита выполнения:

```bash
if [ -x "$proj/.claude/sdx/verify-cmd.sh" ]; then
```

Дальше файл вызывается через `bash -c`, поэтому букву инварианта формы вызова
(`sdx/protocol.md`, «Enforcement-слой», BUG-008) это не нарушает. Но зависимость от режима
файла остаётся: если бит не проставлен или потерян, ветка `-x` не срабатывает, управление
уходит в автодетект (`composer test` / `npm test` / `phpunit`), а в проекте без этих маркеров —
в no-op. Тест-пол под Verification исчезает **молча**: пользователь считает, что stop-gate
держит красный прогон, а он выключен. Это ровно класс [DEBT-010](DEBT-010-silent-hook-degradation-invisible.md).

Риск не гипотетический: шаблон `sdx/templates/verify-cmd.sh.template` лежит в репозитории с
режимом `100644`, а `commands/init.md:40` требует создать из него **исполняемый**
`.claude/sdx/verify-cmd.sh` — то есть корректность зависит от того, что `/sdx:init` не забудет
`chmod +x`, а установщик/синхронизация не срежут бит (наблюдённый сценарий BUG-008: все
`sdx/hooks/**/*.sh` развёрнуты с правами `0600`).

Отложено осознанно: правка меняет **семантику определения тест-команды**, а не форму вызова,
поэтому в patch-сессию BUG-008 не бралась.

## Рекомендация
1. Заменить `-x` на `-f` и вызывать раннер явно через `bash`. Проверить, что нигде не
   задокументировано снятие бита как способ «выключить» per-project раннер — беглый просмотр
   `commands/init.md` и `sdx/protocol.md` такой конвенции не обнаружил, но решение стоит принять
   явно, а не по умолчанию: смена `-x` → `-f` вернёт тест-пол тем проектам, где файл лежит
   неисполняемым.
2. Если opt-out всё же нужен — сделать его явным (пустой файл, комментарий-маркер или
   отсутствие файла), а не свойством режима.
3. Покрыть тестом в `sdx/hooks/test-stop-gate.sh`: `verify-cmd.sh` с режимом `0600` должен
   по-прежнему давать тест-пол (сценарий красный до фикса).
4. Заодно рассмотреть режим шаблона `verify-cmd.sh.template` (`100644`) и надёжность шага
   `chmod +x` в `/sdx:init`.
