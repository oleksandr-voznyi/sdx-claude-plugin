# DEBT-028. Тип сессии `audit` не подтверждён исполнением: REQ-AUDIT-9..15 держатся только на прозе

## Суть
Поставка `feat-audit-agent-20260726` реализовала две половины механизма аудита, но проверила
исполнением только одну. Команда `/sdx:audit` прогнана дважды (мета-репозиторий с полной триадой и
проект-потребитель без неё — протокол в записи `docs/history/sessions-log.md`), а **тип сессии
`audit` не запускался ни разу**. Непроверенным осталось семь требований из шестнадцати:

- `REQ-AUDIT-10` — вход Discovery-lite: валидация пути к отчёту, парсинг frontmatter с полем
  `run:`, стоп-условие при отсутствии `docs/backlog/`. Существует только текстом в
  `commands/start.md`.
- `REQ-AUDIT-11` — обязательный выход этапа `Update`: изменения `docs/backlog/`. Из 92 находок
  отчёта `docs/history/audit/audit-2026-07-26.md` не создано ни одной записи.
- `REQ-AUDIT-12`/`13` — три слоя дедупликации и класс «регресс» против закрытых записей. Ни один
  слой не исполнялся на реальных данных; в частности не проверено, что смысловая сверка
  действительно различает открытую и закрытую запись.
- `REQ-AUDIT-14` — форма `source: <run-id> (<CODE><N>)` нигде фактически не записана в frontmatter
  реальной записи бэклога. Именно на этой форме держится первый (детерминированный) слой
  дедупликации, и именно в ней поставка уже допустила один дефект (run-id в двух несовместимых
  формах, найдено fresh-eyes ревью, FAIL-1) — то есть класс ошибок здесь подтверждённо реален.
- `REQ-AUDIT-15` — идемпотентность повторного триажа: логически непроверяема без хотя бы двух
  прогонов триажа.

Внутри самой сессии-поставки проверить это было невозможно по построению: `/sdx:start` требует
чистого дерева и новой ветки, то есть отдельной сессии.

## Рекомендация
Закрывается первым реальным триажем — он нужен независимо от этой записи, потому что 92 находки
аудита сами в бэклог не попадут:

```
/sdx:start audit docs/history/audit/audit-2026-07-26.md
```

Во время этого прогона осознанно проверить и записать в `change_note.md` сессии: разрешается ли
`source`-ссылка в реально существующую находку отчёта; создаётся ли запись-регресс при совпадении
с закрытой записью (в бэклоге 25 закрытых — материал для проверки есть); не появляются ли дубли
при повторном триаже того же отчёта. Обнаруженные расхождения — правки в `commands/start.md` /
`sdx/protocol.md`, а не в этой записи.
