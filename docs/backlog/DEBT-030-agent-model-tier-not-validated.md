# DEBT-030. Значение `model` во frontmatter агентов не валидируется ничем — тихий сбой в рантайме

## Суть
Ни один тест фреймворка не проверяет допустимость значения `model:` во frontmatter агентов
(`sdx/hooks/test-*.sh` — ноль сценариев). Опечатка или недокументированное значение не ловятся
enforcement-слоем и проваливаются тихо при первом вызове агента через `Task` — тот же класс тихой
деградации, что `DEBT-010`, но в новом измерении: не хук, а frontmatter агента.

ADR-019 ввёл четвёртый тир (`fable`), расширив пространство возможных опечаток с трёх значений до
четырёх. Раскладка тир→ответственность при этом объявлена нормативной и подлежащей пересмотру
только новым ADR — то есть значение поля несёт смысл, а не просто настройку производительности:
агент, у которого тир съехал, продолжит работать, но будет выполнять роль не тем инструментом,
который для неё выбран, и внешне это не проявится никак.

Спецификация поставки `feat-audit-agent-20260726` вывела эту валидацию за скоуп явным текстом,
поэтому дизайн её не закрывал даже при низкой цене реализации — это был бы scope creep против
прямого текста SPEC. Запись существует, чтобы пробел не растворился.

## Рекомендация
Дешёвый детерминированный сценарий в существующем харнесе (`sdx/hooks/`, новый или в составе
`test-hook-wiring.sh`, который уже проверяет соседний класс инвариантов): для каждого файла
`agents/*.md` извлечь `model:` из frontmatter и потребовать принадлежности множеству
`{opus, fable, sonnet, haiku}`. Множество — вторая точка истины, поэтому в том же тесте (или
комментарием рядом) сослаться на ADR-019 как на источник, чтобы при появлении пятого тира правка
была очевидна.

Заодно стоит проверить непустоту `name`/`description`/`tools`: тот же проход, та же цена. Отдельно
полезно, что такой тест поймал бы и обратную ошибку — агента, у которого `tools` включает `Bash`
там, где контракт роли требует его отсутствия (`reviewer` по BUG-004, `auditor` по ADR-019).
