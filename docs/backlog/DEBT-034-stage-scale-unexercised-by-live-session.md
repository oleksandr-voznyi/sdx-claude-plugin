# DEBT-034. Единая шкала этапов не подтверждена ни одной живой сессией

## Суть
`ADR-020` заменил пять треков одной шкалой из девяти этапов и двумя флагами; `sdx-stage.sh`
переписан, два хука сняты, две команды удалены. Доказательная база на момент закрытия поставки:

- **тест-сьют** — 8 наборов, 103 сценария, все зелёные; ключевые сценарии проверены на
  дискриминацию (сломать проверяемое поведение → тест краснеет → вернуть) по `REQ-SCALE-4`,
  `REQ-SCALE-5`, `REQ-LEGAL-1`, `REQ-NAV-1`, `REQ-NAV-2`, `REQ-ENF-2`, `REQ-TEST-1`;
- **прямые прогоны на временных фикстурах** — `init` без `track`, форвард через фолд-кредит,
  откат `--to` с маркировкой, запрет цели вперёд, неподвижность при `no_gates`, взаимоисключение
  флагов, диагностика легаси-имени и пустого `stage`.

**Чего нет: ни одной сессии, реально прошедшей по новой машинерии.** Поставка исполнялась под
**установленной копией плагина 1.7.0**, а не под правленым рабочим деревом: команды `/sdx:*`
сессии `refactor-tracks-collapse-20260901` резолвились в старый код со старой матрицей. Это не
дефект исполнения — иначе поставка меняла бы механизм собственного надзора по ходу работы
(`PROC-020`), — но это означает, что связка «команда `/sdx:*` → новый `sdx-stage.sh` → состояние
сессии» не исполнялась целиком ни разу.

Класс тот же, что у `DEBT-028` (тип сессии `audit` не подтверждён исполнением): требования
держатся на прозе команд и на unit-сценариях, но не на сквозном прогоне. Разница в цене: там
непроверенным оставался один тип сессии, здесь — механизм, через который проходит **каждая**
сессия.

## Рекомендация
Закрывается не работой, а наблюдением: после `/plugin marketplace update sdx` первая же сессия
на 2.0.0 является сквозной проверкой. Что зафиксировать по её итогам:

1. `/sdx:start` действительно пишет `no_code`/`no_gates` и не пишет `track`;
2. `/sdx:next` без аргумента проходит шкалу, пропуская неактивные этапы фолд-кредитом;
3. `/sdx:next --to` откатывает и помечает артефакты, отказывается целиться вперёд;
4. `/sdx:archive` доходит до `Closeout` без прежнего распознавания «трека без Closeout»;
5. для `no_code`-сессии активный набор действительно сужен, а `qa` не вызывается;
6. для `no_gates`-сессии `/sdx:proto` проводит легализацию, снимая флаг.

Первые три-четыре сессии на 2.0.0 стоит вести с повышенным вниманием к отказам `sdx-stage.sh`:
именно там проявится расхождение прозы команд с новыми сигнатурами, если оно есть.

## Зависимости и порядок
Не блокирует ничего, но стоит перед началом волны 1: все её задачи (`FEAT-014`, `PROC-019`,
`FEAT-003`, `FEAT-004`) будут исполняться сессиями на новой машинерии, и дефект в ней удорожит
каждую.
