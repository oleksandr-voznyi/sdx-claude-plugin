# DEBT-041. Anti-overclaim-линт направленный: ловит один порядок слов из двух

## Суть
Проверка `[T24](2)` в `sdx/hooks/test-resume-contract.sh` стережёт формулировки, обещающие
пользователю больше, чем механизм даёт: `/sdx:resume` восстанавливает состояние на момент
последнего ЗАКОММИЧЕННОГО состояния, а не «полностью». Регулярка написана как
`восстанавливает.*(полностью|без каких-либо потерь)` и потому ловит только порядок
«восстанавливает … полностью». Обратный порядок — «полностью восстанавливает» — проходит мимо,
хотя это ровно тот же overclaim и, вероятно, более естественная формулировка по-русски.

Второе: после `normalize` (склейка файла в одну строку ради поиска фраз через переносы) `.*`
действует через ВЕСЬ документ, поэтому теоретически возможно ложное срабатывание на паре слов
из разных разделов. Практически сегодня не срабатывает, но свойство неприятное: линт, который
может соврать в обе стороны, доверия не заслуживает.

## Рекомендация
Расширить шаблон на оба порядка слов и ограничить дистанцию между частями (например, поиском в
пределах предложения, а не всего склеенного файла). Заодно добавить зеркальную проверку: набор
формулировок, которые линт ОБЯЗАН пропускать (корректные, с честной границей) — по образцу того,
как в `MANUAL_TEST.md` этой же поставки был добавлен зеркальный класс для `check_dec` после того,
как ревью нашло в нём ложные отказы. Направленный линт, проверенный только с одной стороны, —
тот же класс дефекта.
