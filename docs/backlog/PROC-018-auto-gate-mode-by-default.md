# PROC-018. Авторежим гейтов по умолчанию (инверсия ADR-014)

## Суть
Механика авторежима уже написана и работает: `gate_mode: auto`, `auto_decisions.md`, стоп-рубрика,
дисклоуз одним блоком перед Closeout. Но она opt-in, а дефолт — подтверждение каждого прозаического
гейта. При переносе оси гейтирования с этапа на свойство действия (`FEAT-006`) прозаические
подтверждения переходов теряют смысл: они подтверждают церемонию, а не риск.

## Рекомендация
Инвертировать: `auto` — дефолт, `interactive` — opt-in для высокорисковых контуров и для случаев,
когда карта освоенности пуста. Стоп-рубрика сохраняется полностью и дополняется рубрикой
`FEAT-006`/`PROC-020`.

**Предохранители, без которых инверсия недопустима:** доказанная живость enforcement (`FEAT-014`),
работающая проекция полномочий (`FEAT-010`), и правило «незнание фейлится закрыто» (`FEAT-009`).
Без них инверсия — не смягчение церемонии, а снятие надзора.

## Зависимости и порядок
Формально волна 2 (правка простая), фактически включать только после волн 3–4.
Груминг должен решить: переписывается `ADR-014` или заводится новый ADR с пометкой
«пересматривает ADR-014» (прецедент — `ADR-012` относительно `ADR-009`).
