# PROC-019. «Прогон» как durable-единица работы вместо «сессии»

## Суть
Сегодня единица работы — сессия, и она совпадает с одним инстансом CLI (`ADR-012`: весь
жизненный цикл в одном CLI, хендоффов нет). Состояние частично живёт в контексте модели:
`checkpoint.md` — прозаическая суммаризация для человека, а не точка возобновления. Падение CLI,
`/clear` или смена машины требуют участия человека для восстановления смысла работы.

Durable-движок оперирует не сессией, а **прогоном** (run), переживающим смерть процесса,
сброс контекста, перезапуск и смену модели. Сессия остаётся тем, чем является физически —
одним инстансом CLI; прогон становится тем, что versioned на диске.

## Рекомендация
Ввести понятие прогона с каталогом состояния, полностью реконструируемым с диска, и команду
`/sdx:resume`. Ввести машиночитаемый критерий приёмки, годный как eval:

> **Kill-test.** Убить CLI в произвольной точке прогона, запустить заново с пустым контекстом —
> `/sdx:resume` восстанавливает прогон полностью из диска, без человека и без чтения истории чата.

Это же снимает двойное назначение `/sdx:checkpoint` (`IDEA-004`): суммаризация для человека и
точка возобновления перестают быть одним файлом.

## Зависимости и порядок
Опирается на `FEAT-003` (реестр) и `FEAT-004` (журнал) — без них восстанавливать нечего.
Kill-test является приёмочным критерием для всей волны 1.
