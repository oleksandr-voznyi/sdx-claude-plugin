# PROC-028. Политика вендоринга sim-kit в плагин: версия, обновление, запрет локальных правок

## Суть
`FEAT-015` вносит в плагин код из другого репозитория с собственным циклом выпусков: `sdx/mo/` — копия
`core/mesh_endpoint.py`, `core/devagent_hook.py`, `core/MO-INTEROP.md` из `aibok/agentico/meta-orchestrator/sim-kit`.
У sim-kit своя версия (`VERSION`, хеши ядра в `RELEASES`), свой регрессионный сьют (`tests/kit.sh`), свой механизм
обновления пилотов (`upgrade.sh` с классами «заменить / слить вручную / не трогать»). Это первый фрагмент плагина,
который не является ни bash+jq, ни документом: чужой python-код, который плагин исполняет хуком (через
bash-обёртку, `FEAT-015` п.2 — поэтому python3 и PyYAML остаются зависимостью проектов под МО, а не плагина).

Без явной политики возникает ровно та ситуация, от которой ушёл ADR-013: две копии (sim-kit и плагин, плюс ручные
`tools/mo/` в пилотах до выпуска плагина) разъезжаются по версиям, а дефект, найденный в плагине, чинится локально
и теряется для upstream. Прецедент уже есть: семь находок по 0.7.2 SDX **не мог** исправить у себя — только
запиской в sim-kit (`SDX-MO-interop-reply-2026-10-04.md`); так и должно оставаться.

## Рекомендация
Зафиксировать в `sdx/protocol.md` (там, где описан enforcement-слой и его зависимость от `jq`) и в `sdx/mo/README`
или `SIMKIT_VERSION`:
1. **Источник истины — sim-kit.** Плагин вендорит ровно файлы выпуска с версией из `VERSION`; локальные правки
   вендорённого кода запрещены — дефект уходит запиской в `agentico/reviews/`, плагин ждёт выпуска. Это
   **именованное исключение** из инварианта ADR-013 «источник истины фреймворка — этот репозиторий»: для
   `sdx/mo/` источник истины — sim-kit, и исключение записывается в ADR-013 поправкой, а не подразумевается.
2. **`SIMKIT_VERSION`** в `sdx/mo/` — единственное место, где версия названа, плюс sha256 каждого вендорённого
   файла на момент обновления (`RELEASES` sim-kit для сверки непригоден: он хеширует только `core/mo.py`, который
   не вендорится). Документы плагина ссылаются на файл, не дублируют число (по образцу `DEBT-006`/ADR-008 для
   раскладки моделей).
3. **Обновление — осознанный шаг** отдельной сессией и не в автономном режиме (`PROC-020`: обновляется механизм
   надзора): прогон `tests/kit.sh` sim-kit (часть, относящаяся к
   лист-сессии) против вендорённой копии, прогон собственных тестов плагина на хук, запись в `CHANGELOG`/релизные
   заметки с номером версии sim-kit. Автообновления нет.
4. **Совместимость протокола**: конверт `v` и списки `MAY_SEND`/`MAY_RECV` — часть контракта; смена `v` в sim-kit
   = мажорный повод для обновления плагина, не минорный.
5. **Сторож инвентаря** (`PROC-027`): поверхность, пересказывающая состав `sdx/mo/` (README плагина, `CLAUDE.md`),
   проверяется тестом против фактического содержимого каталога.

## Зависимости и порядок
Перед `FEAT-015`: политика — условие входа, не следствие. Небольшая по объёму (`change_note.md`), но решение
о запрете локальных правок и исключение из ADR-013 принимает человек и фиксирует поправкой к ADR — не
оркестратор дефолтом. Приоритет — не ниже, чем у `FEAT-015`: условие входа не может ждать дольше следствия.

## Резолюция
Закрыто сессией `proc-028-simkit-vendoring-20261004`. Поставлено: подраздел «Вендорённые компоненты
(`sdx/mo/`)» в `sdx/protocol.md`; датированная поправка к ADR-013 (именованное исключение из инварианта
«источник истины — этот репозиторий»); статический сторож `sdx/hooks/test-mo-inventory.sh` (состав, хеши,
плоский каталог без `__pycache__`, упоминание каждого вендорённого имени в `README.md`, `README.en.md`,
`CLAUDE.md`, протоколе и ADR — п.5 рекомендации; зелёная сторона, `sha256sum -c`-совместимость, красные
стороны для каждой ветки, 17 проверок); `FEAT-015` п.1–2 приведены к политике (`PYTHONDONTWRITEBYTECODE=1`
в обёртке, критерии приёмки).

**Отступления от рекомендации.** П.2: вместо sha256 внутри `SIMKIT_VERSION` — два файла, `SIMKIT_VERSION`
(версия) и `SIMKIT_SHA256` (формат `sha256sum`), чтобы сверка руками была одной командой без парсинга.
П.3: «не в `gate_mode: auto`» — норма протокола, хуком не enforced — `DEBT-042`. Каталог `sdx/mo/` этой
сессией не создан (пустой вендоринговый каталог в поставке — шум); сторож активирует проверку реального
каталога и поверхностей с `FEAT-015`, до этого честно печатает INFO.
