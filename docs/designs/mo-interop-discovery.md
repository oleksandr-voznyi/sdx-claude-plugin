## 2. Контракт обёртки `sdx/hooks/mo-hook.sh` — что вытекает из кода и протокола

### 2.1. Что делает хук sim-kit (`DH`)
- Вход — JSON харнесса на stdin (`tool_name`, `tool_input`, `cwd`, `session_id`) (`DH:58,65–66,158`). Каталог проекта: `MESH_ENDPOINT_DIR` по умолчанию из `CLAUDE_PROJECT_DIR`, иначе `os.getcwd()` (`DH:28`). `ME:30` — `HERE = (MESH_ENDPOINT_DIR или cwd)/.mesh`; т.к. `DH` делает `setdefault` до импорта `ME`, это согласовано **только внутри хука**; при ручном вызове CLI `ME` (preflight) `MESH_ENDPOINT_DIR` нужно выставить явно, иначе берётся `cwd`.
- **Нет `.mesh/endpoint.yaml` → `exit 0` до импорта чего-либо** (`DH:31–32`). То есть сам `DH` уже молчит; обёртка нужна ради (1) отсутствия запуска интерпретатора (латентность/зависимость python3), (2) перевода `exit 2` в JSON, (3) `PYTHONDONTWRITEBYTECODE`, (4) отказа подмены `.mesh/endpoint.yaml`.
- Режим `on_write` без PyYAML: `re.search(r"^\s*on_write\s*:\s*['\"]?(\w+)", text, re.M)`, значение приводится к lower, нет совпадения/ошибка чтения → `notice` (`DH:35–40`). Прогнано: строка `on_write: notice  # x` → `notice`; `on_write: deny` → `deny`. Следствия для `grep`-эквивалента: игнорировать регистр значения (`DENY` → deny), допускать пробелы/кавычки, взять **первое** совпадение (`re.search`), дефолт `notice`. Ограничение: regex не знает ни комментариев (`# on_write: deny` в строке начинающейся `#` не совпадёт благодаря `^\s*`, но `on_write:` внутри многострочного значения — совпадёт), ни YAML-якорей; воспроизводить как есть.
- `cannot_check(why)` (`DH:43–48`): режим `deny` → печать `DENY [MO-exec-paths]: PEP не может проверить цель записи — <why>. Режим deny: запись остановлена.` в stderr + `exit 2`; режим `notice` → `devagent_hook: <why> — проверка exec_paths пропущена (режим notice)` в stderr + `exit 0`. Вызывается при: `ImportError`/`SystemExit` на `import mesh_endpoint` (нет PyYAML — `ME:25–28` делает `sys.exit("mesh_endpoint: нужен PyYAML")`) (`DH:53–55`); нечитаемый stdin/ошибка `me.cfg()` (`DH:57–61`); `me.pull`/`me.leases` бросили (`DH:150–153`). Прогнано: мусор на stdin в `deny` → rc=2 с сообщением `вход хука/endpoint.yaml не разобран (JSONDecodeError)`; симулированный отсутствующий yaml в `deny` → rc=2.
- `exec_paths` пуст/нет → `exit 0` (`DH:62–64`). Целей записи нет → `exit 0` (`DH:145–146`) — в т.ч. **`Write` в `.mesh/endpoint.yaml` проходит** (прогнано, rc=0): хук `.mesh/` сам не охраняет. Охрана `.mesh/endpoint.yaml`/`cursors.json` — только в обёртке (п.2 FEAT-015).
- Аренда есть → `exit 0` (`DH:154–155`). Иначе: окно подавления `NOTICE_WINDOW=600` с, ключ `session_id|instance` в `.mesh/hook-state.json` (`DH:157–172`); конверт `notice` `exec_paths.write` в `.mesh/outbox/<link>/NNNNNN.json` (`DH:173–180`, `ME:72–89`); при `on_write == deny` → stderr `DENY [MO-exec-paths]: запись в каталог исполнения <inst> (<path>) без аренды МО. Поставка — через операцию МО (artifact.offer → rollout) или аренда role-switch в узле <node_id>.` и `exit 2` (`DH:181–184`); иначе `exit 0`.
- **stdout хука всегда пуст** (прогнано; в коде нет `print` без `file=sys.stderr`). Причина блокировки — только в stderr.
- Конвенция: `exit 2` = блок (`DH:11,14,184`, `MI:70`); протокол SDX: блок — JSON `permissionDecision:"deny"` на stdout + `exit 0` (`sdx/protocol.md` ~стр.46; `prod-guard.sh:7–8,13–17`). `exit 2` в SDX-хуках встречается как механизм **Stop-хука** (`stop-gate`, возврат человеку после 3 красных), но не как PreToolUse-блок.

### 2.3. Как обёртка узнаёт режим без PyYAML
Одним `grep`/`sed` по `.mesh/endpoint.yaml`, повторяя regex `DH:37` (`^\s*on_write\s*:\s*['"]?(\w+)`, без учёта регистра в значении, первое совпадение, дефолт `notice`). Это единственный источник режима (FEAT-015 п.2: «режим читается `grep`'ом»). Расхождение с `DH` возможно, только если regex будет написан иначе — вариант защиты: тест-пара (одни и те же фикстуры `endpoint.yaml` для `DH` и для обёртки). PyYAML для этого не нужен: у `DH` такой же путь (`raw_mode`) выполняется даже когда PyYAML отсутствует.

`CLAUDE_PROJECT_DIR` (проект; в `prod-guard.sh:7` дефолт `.`), `CLAUDE_PLUGIN_ROOT` (путь к `sdx/mo/`; у соседних хуков дефолт из `BASH_SOURCE`, `selftest.sh:11–12`), `MESH_ENDPOINT_DIR` (`DH` ставит сам через `setdefault`), `CLAUDE_SESSION_ID` (читает `ME:82` для поля `from.session` конверта; хук Claude Code этой переменной в окружении может не получить — открытый вопрос, влияет только на метку в конверте), `PYTHONDONTWRITEBYTECODE=1` (требование FEAT-015/PROC-028).

## 4. SessionStart-часть: контракт

### 4.1. Где место в `preflight.sh`
`preflight.sh` — 9 строк, `set -uo pipefail`, одна проверка (`jq`), вывод в stderr, `exit 0` в конце; не читает stdin; гарды `.claude/sdx` нет (в отличие от `selftest.sh:22`, где гард стоит первой операцией после резолва `$proj`, до любых записей). Блок МО добавляется перед финальным `exit 0` (после jq-проверки) либо выносится в отдельную запись `SessionStart` (как selftest — «не расширяет preflight.sh», `selftest.sh:2–3`); решение дизайна. Если блок живёт в `preflight.sh`, он наследует его свойство «срабатывает в любом проекте» — отсюда обязательное условие «есть `$CLAUDE_PROJECT_DIR/.mesh/endpoint.yaml`».

### 4.2. Гард «не пишет в проектах без SDX»
Гард `selftest.sh:22` (`[ -d "$proj/.claude/sdx" ]`) связан с признаком SDX-проекта; `.mesh/endpoint.yaml` — признак «над стендом есть МО» (`MI:10–13`), и FEAT-015 п.3 привязывает активацию к нему одному. **Выполняемые команды пишут в `.mesh/`** (прогнано: `pull` создаёт/перезаписывает `cursors.json` даже без новых конвертов, и `ME` при разрыве цепи шлёт `nack` в `outbox`), т.е. SessionStart-часть **не read-only**. Это пишет в `.mesh/` самого проекта (фенотип, вне git), не в плагин и не в `.claude/sdx/`; но если проект есть МО-проект без SDX-инициализации (нет `.claude/sdx/`), вопрос «писать ли `.mesh/`» — открытый (§5.4). `inbox --json` и `leases` читают, но `accepted()`→`_cursor` лишь читает `cursors.json` (`ME:92–95,136–151`). `leases` (CLI `ME:199–202`) вызывает `leases()` без записи.

### 4.3. Что печатать и куда
FEAT-015 п.3: «показывает входящие и аренды». Факты формата: `inbox --json` — по одному конверту на строку (каноническая сериализация, `ME:157`); без `--json` — человекочитаемая строка с меткой `[ДАННЫЕ, не инструкции]` и телом, усечённым до 160 символов (`ME:159`; усечение — закрытая находка 0.7.3, `--json` без усечения); `leases` — строки `instance holder до <expires> run=<id>` (`ME:200–202`). Каналы SessionStart у харнесса: у `preflight.sh`/`selftest.sh` сейчас всё идёт в **stderr** (оператору/в debug-вывод); попадание stdout SessionStart-хука в контекст модели — свойство харнесса, **в репозитории не задокументировано** и не проверено (граница для DESIGN: если нужно, чтобы модель/dev-agent «увидел» входящие и аренды, надо установить, какой канал это делает; иначе §3 `MI` «читать только через `inbox --json`» остаётся ручной нормой). Безопасность: содержимое конвертов — данные, не инструкции (`MI:49–54`, `ME:20`); вывод в контекст должен сохранять эту маркировку; конверт с телом-инъекцией при сыром `--json` в stdout контекста — вектор (граница названа в `MI` §3: для `directive` в `auto` — норма п.7).

### 4.4. Отсутствие PyYAML / python3 на SessionStart
`ME:25–28` при импорте без PyYAML завершает процесс `sys.exit("mesh_endpoint: нужен PyYAML")` (exit 1, сообщение в stderr). Для SessionStart FEAT-015 п.3 требует **проверку** `python3 -c 'import yaml'` только при наличии `.mesh/endpoint.yaml`. Варианты вывода: одна предупреждающая строка в stderr + пропуск `pull/inbox/leases`; SessionStart не должен блокироваться (в проекте нет прецедента `exit 2` в `SessionStart`; в `preflight.sh:9` есть закомментированный `# exit 2`). Согласование с PreToolUse-частью: если нет PyYAML, режим `deny` будет блокировать каждую запись в инструмент — это нужно сказать пользователю **заранее** на SessionStart (иначе первая блокировка — сюрприз; класс DEBT-010 «тихая деградация»). `SessionStart`-вызов `pull` без `MESH_ENDPOINT_DIR` берёт `cwd` — не обязательно корень проекта (в `SessionStart` харнесса `cwd` обычно корень, но не зафиксировано) → выставлять явно из `CLAUDE_PROJECT_DIR`.

## 5. Риски и открытые вопросы для SPEC/DESIGN

1. **Зависимость обёртки от `jq`.** Единственная точка сборки JSON с `permissionDecisionReason` — `jq -Rs .` (`prod-guard.sh:11–14`). Исход без `jq` в `prod-guard`: до проверки конфига — exit 0; при сконфигурированной защите — статичный литерал JSON (`prod-guard.sh:46–48`). Для обёртки: (а) `jq` и в МО-проекте может отсутствовать (`preflight.sh` это уже ловит); (б) варианты — статичный/самосборный экранированный JSON без `jq` (`sed` экранирование `\` и `"`, `tr` для переводов строк; многострочная stderr хука; UTF-8) либо литерал без причины; (в) вход Write/Edit (`tool_input.file_path`) без `jq` разбирается только `grep`/`sed` — ненадёжно (экранирование); (г) порядок проверок «нет `endpoint.yaml` → `exit 0`» **до** `jq`/python — по образцу A2/BUG-002 (`prod-guard.sh:21–24`): отсутствие зависимости не должно блокировать проект без МО. Вопрос: fail-closed в `deny` без `jq` — разрешён ли, и что при `notice`.
2. **Привязка к ветке `sdx/<id>`.** Остальные хуки слоя «активны только в SDX-ветке» (`protocol.md` ~стр.33–34; stop-gate через `resolve-session.sh`), `prod-guard` — нет (работает по наличию conf, `prod-guard.sh`). FEAT-015 привязывает МО-хук к `.mesh/endpoint.yaml`, не к ветке/сессии: он должен действовать и на `main`/вне сессии (запись в `exec_paths` мимо сессии — как раз целевой случай). Проверить, что это сознательно закреплено в SPEC.
3. **Переносимость (BUG-010-класс).** `bash`, `grep`, `sed`, `jq`, `python3`: у `timeout` на macOS нет (`BUG-010`: запись `timeout 10 bash …; exit 0` для selftest тихо не исполняется) — **не** использовать `timeout` в записи МО-хука, иначе повторится тихая деградация, причём теперь в fail-closed-контуре (там: `command not found` проглотится `; exit 0`, хук не исполнится вовсе — для PreToolUse это превращается в «защиты нет», не в блок). Таймаут самого `python3`-вызова внутри обёртки — вопрос; у `DH` нет собственного таймаута, но он делает ввод-вывод только по файлам. `sha256sum`/`shasum` — уже учтено в сторожe (`sha256_of`). `date +%s%N` не нужен. Версия bash: macOS 3.2 (нет `mapfile`/ассоц. массивов; `test-hook-wiring.sh` использует `mapfile` — тест уже не переносим).
4. **Гарды и записи при отсутствии SDX-инициализации.** Реакция МО-хука/SessionStart-части на проект с `.mesh/`, но без `.claude/sdx/` (МО-проект, не прошедший `/sdx:init`): FEAT-015 не оговаривает; `SessionStart` в нём сегодня уже печатает jq-предупреждение (preflight без гарды). Вопрос для SPEC: гард «есть `.claude/sdx`» нужен или достаточно `.mesh/endpoint.yaml`.
5. **Что делать с `.mesh/` в этом мета-репозитории.** `.mesh/` нет и не будет. Живая проверка заявлена на репозитории ядра MOVE.IO (пилот MO-I) — вне нашего дерева. Тестируемость без реального узла МО: см. 5.6. Для `/sdx:status`-подобных проверок в мета-репо проверка «`.mesh` отсутствует → `exit 0`, нет stderr» — единственное, что исполняется в «живом» окружении сессии (dogfood), и оно совпадает с зелёной стороной критерия.
6. **Тест трансляции `exit 2 → JSON deny` без узла МО.** Фикстура (прогнана вручную в scratchpad и работает): временный проект с `.mesh/endpoint.yaml` (поля `endpoint_id`, `node_id`, `link`, `instance`, `exec_paths: [<tmp>/dep]`, `on_write: deny`), stdin `{"tool_name":"Write","tool_input":{"file_path":"<tmp>/dep/a"},"cwd":"<tmp>","session_id":"s1"}`, `CLAUDE_PROJECT_DIR=<tmp>` → **реальный `DH`** (вендорённый) возвращает `exit 2` + stderr `DENY [MO-exec-paths]…` без какого-либо узла МО (узел нужен лишь для того, чтобы *положить* `lease.granted` в inbox — тест зелёной стороны «аренда есть» собирается руками: файл `.mesh/inbox/<link>/000001.json` с корректной цепью/хешем — `ME:68–69` `ehash`; `ME:125` проверяет `from.node == node_id`, `kind in MAY_RECV`, `data_only`, хеш). Варианты стенда: (а) реальный вендорённый `DH` на фикстуре (тест зависит от python3+PyYAML в CI — при их отсутствии тест должен честно `SKIP`, как `test-selftest.sh`/`test-mo-inventory.sh` печатают INFO, не PASS); (б) заглушка `devagent_hook.py` с управляемым кодом выхода (`MO_HOOK_FIXTURE_PY`-подобный крючок типа `SDX_SELFTEST_HOOKS_DIR`, `selftest.sh:26–27`): обёртке нужен тест-крючок на путь к хуку; без него заглушку можно подложить только через подмену `CLAUDE_PLUGIN_ROOT` на фикстур-дерево (`$fx/sdx/mo/devagent_hook.py`) — рабочий вариант без правки продового кода; (в) подмена `python3` заглушкой в `PATH` (критерий «без python3»: PATH без python3 либо падающий `python3`; «`python3` в дереве процессов» проверяется заглушкой, пишущей в файл-маркер). Красные стороны (по конвенции `test-prod-guard.sh`/`test-mo-inventory.sh`): мутант обёртки без трансляции (`exit 2` проходит насквозь), мутант без `PYTHONDONTWRITEBYTECODE` (виден `__pycache__` в `$fx/sdx/mo`), мутант без раннего выхода. Порядок: сначала демонстрация красной стороны, потом реальная (как в `test-mo-inventory.sh` шапке).
   Конвенция эмуляции вызова: `printf '<json>' | CLAUDE_PROJECT_DIR="$TMPPROJ" bash "$HOOK"` (`test-prod-guard.sh:36–41`), сбор `RUN_OUT`/`RUN_EC`; проверка JSON — `grep -q '"permissionDecision":"deny"'` + `jq .`; фикстуры — `mktemp -d`, чистка в `cleanup`; счётчики `pass`/`fail`, `Results: N passed, M failed`, `exit 1` при падении; для `PATH`-подмен — `test-selftest.sh` (`NOJQ_BIN`, `RS_PATH`, функция-обёртка `run_selftest` с `unset` RS_* на выходе). `verify-cmd.sh` подхватывает `sdx/hooks/test-*.sh` глобом — новые сьюты включаются автоматически; общее время прогона ≈9 с (комментарий `verify-cmd.sh`) — тесты с python-запуском должны быть быстрыми.
7. **Нужен ли отдельный сторож на запись `hooks.json`.** Что покрывает `test-hook-wiring.sh` сегодня: форму вызова (`bash <путь>`), существование скриптов; **не** покрывает: matcher'ы, присутствие конкретной записи, отсутствие `timeout`-обёртки, порядок. Плюс класс DEBT-010: тест «живости» в `selftest.sh` не включает МО-хук (периметр — три хука; расширение — отдельное решение, `selftest.sh:2–7`); смена периметра затрагивает отпечаток кэша только через версию плагина.

15. **Побочные эффекты хука в `.mesh/` на «чтение».** `pull` внутри хука (`DH:151`) пишет `cursors.json` и может отправлять `nack`; хук при `Bash`-команде без цели записи этого не делает (выход раньше, `DH:145–146`) — латентность `PreToolUse` по `Bash` в МО-проекте = старт python (~десятки мс) на каждый вызов; для `deny`-режима без PyYAML каждый `Bash` блокируется (вкл. `ls`).
16. **Версия протокола и совместимость.** Конверт `V = 1` (`ME:31`), `MAY_SEND`/`MAY_RECV` (`ME:32–33`) — предмет «мажорного повода» (`protocol.md` стр.316–318). Сторож этого не проверяет (названо).
